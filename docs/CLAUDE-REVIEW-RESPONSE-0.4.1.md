## 14 项审核意见逐项处置

| 审核项 | 实施与证据 |
|---|---|
| N0-1 占位开球 | 首次使用先取目录、赛果，再核对逐场赛程。内置赛季文件的占位值等待两源依据后才供新闻采集与事件预测使用。固定 B1 窗口遇到已知冲突、撤回或整轮未获佐证的占位时间时会等待，记录具体原因。具名改期需有原件和决定记录。 |
| N0-2 原地升级 | 值守在封存窗之前核对已生效和已安装的物理版本，未批准时给出缺少基准、对照或具名决定的具体步骤，仍可继续采集。测试库的签核只对自己的数据目录生效。 |
| N0-3 训练新鲜度 | 新命令从实际可验证的训练清单计算截止时可训练的样本，同时列出轮次、逾期、隔离及下一轮逐队阻断。总体存在历史缺口与下一轮可以开始封存可以同时发生。 |
| N1-1 反复归档 | 每次轮询留存响应凭据，同一球员实质状态不变时复用版本。用原审核脚本重放 4 人、72 次轮询，旧版有 288 个状态版本，新版有 4 个、72 次轮询凭据。已过保留期且属于完赛比赛的旧原件可以按 SHA 无损压缩。保留策略及压缩的年龄、受影响范围可先用 `news retention --days 90` 查看。 |
| N1-2 改期丢失消息 | 按同一比赛身份重查原始报名、当时可见的名单、适用窗口及新比赛时间。早先的封存按原样可读。沿用 Claude 探针，更正后原 3 条事实立即可见，下一次轮询及三小时后仍为 3 条，包含俱乐部的官方 RSS。 |
| N1-3 整队弃收及来源集中 | 结构化伤停按字段直接转成状态。异常行隔离，姓名没有唯一匹配时记录数量并标记该源覆盖不完整。整份响应仍需要通过来源与使用许可校验。本次实际进入调整的 81 条状态仍全部来自 Touchline，已登记适合的一手源才会带来实际的来源多样性。 |
| N1-4 杯赛、代词及引语 | 区分受伤经过和将缺席的目标赛事，允许有明确依据的同一球员上下文。解析器保留受支持引语模板中的文字。旧版归档中已删除的引语无法从简化文本还原。历史重跑使用固定出版证据，仍保留严格本机赛前收件为零的分母。 |
| N2-1 评估功效 | 保留原有整季赛果判定，并新增分时点、模式和概率方法的跨季描述性研究。比较有新闻与无新闻两组离同一真实收盘参考的距离，单列两次原生盘口的缺口。提前登记关心的差异、波动假设、按轮区间和可检测幅度。研究方法身份与整包升级签核分别验证。 |
| N2-2 同位置球员权重 | 引入免费英超球员出场分钟和首发次数，或已确认首发阵容的累计占比。队伍数据可对账且球员身份唯一时才使用。实采 20 队，在 81 条进入调整的球员状态中，44 条用了首发和分钟权重，37 条回退至位置先验。 |
| N2-3 长期伤停、出场概率和断流 | 伤停按连续状态首次实收时间衰减，持续到 42 天时权重为零。有效上游出场概率折成缺席概率；二手伤停的权重上限为 0.45。最近有效收件及来源快照均受 6 小时时限约束。旧截止点只可见当时的确认。 |
| N2-4 语言评测口径 | 结构化字段和人工编写句例保留各自分母。另用 16 家俱乐部、32 篇真实文章的短摘录做逐项标注和评测，31 条标注事实中完整识别 11 条，提取的 16 条中 11 条四项全对。这是 Codex 单独标注、给定候选名单的正文测试，尚未做独立人工复标。 |
| N3-1 发布标识 | 补列旧版三个公开开发阶段的 Git 提交与完整 tree；其中后两个 tree 与原签署记录一致。最初的本地暂缓候选当时没有留下 tree，无法证明同一性。本版独立签署使用可从公开仓库重查的树对象。 |
| N3-2 概率可复算性 | 新的真实事件导出直接给出两组主客进球率、ρ、全部概率、各线双向和截尾依据。旧版 10 场事件当时公开的仅有 120 个概率，另作参数反推并明确将衍生值标作重建。 |
| N3-3 首次顺序与测试 | 手册加入运行就绪检查、升级顺序和历史基准恢复路径。回归包含多次轮询、先采再改时、过期和身份缺口。CI 对 Python 3.11、3.12、3.13 分别执行浏览器用例，并对归档、比分有效性和按轮区间三个模块做严格类型检查。 |

## 能从本次数据得出什么

本次赛前检查的 60 个流中，54 个完整、6 个部分成功，7 行球员身份无法唯一匹配，另有 1 行异常。得到 142 个消息版本和 94 条具名结论。10 场产生事件预测，6 场双方都有完整覆盖。未覆盖的场次仍可查看已核实的单项来源和概率，累计研究单独审查其配对资格。超过各源的刷新间隔后，第二次在线检查了这 60 个流。20 队伤停响应的原始哈希全部改变，球员实质状态都没变，系统新增伤停版本和伤停结论均为 0。两次之间升级了提取器，旧转会材料补记 13 条结论，传闻的概率权重为零。[两次实采的数字与逐队凭据](../reports/news-operations-0.4.1.json)

同一批公开历史修订重建 2025/26 前 3 轮共 30 场。只使用球队页面时，两组均为 73.640724 分。在预定球衣号码的球员页面也纳入的口径，补识麦迪逊长期伤缺后，1 场发生变化，无新闻均分 73.640724，有新闻均分 73.636464。该个例已用于修正规则，这个 30 场回看不能作为独立的前向验证。[固定历史输入和逐场结果](../reports/news-history-0.4.1.json)

复跑 Claude 固定种子的 2,000 个模拟赛季，按原十场事件的变化幅度、假设有新闻组就是真实概率，原整季规则给出“更好”的比例为 1.0%。这个数字依赖所用分布和假设。本次真实第 12 轮固定决策窗尚未到达，合格 T−60 配对、已评分场次和配对收盘样本均为 0。按真实开球计算收盘距离时还缺一项数据。默认版批准的免费开球事件源为 0，值守副本也没有实际开球凭据。单靠等待本轮完赛无法补足这一项，须取得允许此用途的事件原件并核验具体比赛。赛果评分仍可继续。现有实测数据不足以判断新闻能提高预测质量或模拟收益。[原功效探针与场景](review-evidence/code-review-0.4.0-2026-11-25/outputs/probe-power.json)

## 独立复审追加的修订

独立审核在发布前复现了一次并发错误。利兹联一场的赛程在新闻预测已算好、尚未写入时出现两源分歧。新版在写入的同一数据库事务内重新核验两份原件、时效和撤回记录。复验中，利兹联的记录保持第 1 版，森林的第 2 版正常写入。两源重新确认后，利兹联才写入第 2 版。

研究版本现在也对把来源字段转成球员结论、保存首见时间、记录收件证明的代码求摘要。改变这些处理会分开计算两种实现的前向成绩。单纯改变轮询间隔或数据库索引时可以继续累计同一组样本。

赛季服务一度能在五分钟决策窗开端封存预测，却可能在十多分钟前才取过盘口。现在两种决策窗各加 15 次原生批量盘口请求，每 20 秒一次；继续保留原有决策、执行和收盘请求。审核员用第 12 轮真实赛程逐秒检查所有 10 场，修订前两个窗口距上一计划请求最多为 874 秒及 59 秒，修订后均为 25 秒。联网故障或实际收件迟到的比赛仍逐场记缺，当次迁移复验产生的盘口收件为 0，既有 748 个决策、执行、收盘及纸面操作时段按原样保留。[森林对切尔西逐个采样时刻及原计划迁移记录](../reports/news-decision-book-plan-0.4.1.json)

轮报、赛季报告及跨季研究会同时列出合格新闻封存、有实际开球凭证、配齐盘口这三个分母。默认开球事件源未就绪时，零样本的报告也会显示原因。已归档的旧凭据按当时的许可与原件重新验证。[第 12 轮及跨季研究的实际缺口](../reports/news-study-readiness-0.4.1.json)
