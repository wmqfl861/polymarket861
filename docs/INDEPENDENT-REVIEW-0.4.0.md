| 首轮发现 | 修订后的独立复验 |
|---|---|
| 名单撤回后原有球员仍影响预测 | 在真实切尔西名单副本上通过来源适配器撤回名单。旧时点仍为 30 名球员、7 条事实，新时点为 0 名、0 条。覆盖同人被两队同时登记、名单到期、计算过程中名单变化以及恢复后的调度。 |
| 后到的二手转述降低了官方确认的权重 | 官方先确认缺阵，另一媒体随后同意。正常入口仍返回已确认缺阵、原有权重，无新增预测。回归覆盖标注相同出处和独立媒体两种转述。 |
| 尚有 RSS 待处理条目时错误显示已覆盖，滚动窗口可能丢失原文 | 原生响应含 101 条，唯一缺阵在末项。首批处理后显示未读完，覆盖为否。第二次请求时供应方已删除末项，仍可从首份收件恢复该项、保留最初实收时间和后续提取时间。跨进程回归通过，全部处理后覆盖才成立。 |
| 单一人工导入的比分可进入新闻评分 | 用正常录入入口写入 29–0，已封存配对为 1，已核实、已评分均为 0。另复验两份已准入来源支持的 0–2、后修正至 3–0、撤回和原件损坏。已有预测的摘要保持可读。真实第 4、10、11 轮共 30 场的独立库副本中，旧版与新版对 19 场准入、11 场缺证的全部证明对象逐字节一致。 |

| 另一场的对手、过去的伤缺被用于当前比赛 | 森林对切尔西，句子中明确写去维拉客场或迎战维拉时不影响本场，改为切尔西则确认缺阵。同一句先说上周缺阵、再说将回归名单时，输出可出场并保留完整原句。历史材料中热刺球员在对纽卡斯尔的友谊赛受伤，已从对伯恩利的样本中排除。 |
