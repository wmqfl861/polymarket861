## 赛前赛果怎样映射到合约

| 家族 | 身份与概率事件 | 进入预测和结算的条件 |
|---|---|---|
| 胜负 | `moneyline`，两个球队结果。将结果名及其同位置的 token 映射到对阵球队 ID | 读取该合约决定胜方的时间范围。样本 11/11 对胜负明写包括加时。常规时间打平进入加时，最终胜负不设置第三个可买的“平” |
| 全场大小 | `totals` 加 `full.total`，从联合分布求两队总分对阈值的尾部概率 | 样本 330 条均为半分线，逐条正文给出达到某个整数算大。本样本这 330 条正文均未明写 overtime。把同期完整规则、官方终场定义与同模板真实兑付列入审核 |
| 单队大小 | `team_totals` 加 `full.team_total.home/away`；用该队最终分数的边际分布 | ID 还要对上事件的球队、主客标记与正文中指定队名。104/104 明写只算该队且包括全部加时。同期另有 96 个 `first_half_team_totals` 和 701 个球员 `points`，全部分流 |

## 价格与费用

1. 保存每个 token 的双边档位、每档价量、盘口时间及实收时间、tick、最小量、可接单状态、费率对象与条款哈希。校验回包的令牌、条件、重复项、缺项、买卖倒挂和两时点规则变化。盘口的最近变化时刻与本机在指定窗口内实收是两个字段。旧盘口时间、陈旧缓存、无卖家和真实禁止交易各自展示。
2. 买入按实际卖方深度从低价到高价累积，超出预算或冻结限价即停。首个决策时点冻结方向、线和金额，预设模拟提交延迟后再次读取**同一**合约的盘口并确认仍未开球。合格则按该实收执行簿模拟至深度足够、限价或剩余预算耗尽；部分成交与不成交单列。记录毛份额、费用计价单位、净份额、总出资与已兑现金。锁定至市场最终兑付，不制造中途平仓。
3. 价格 0.39 表示每份的卖方报价。胜方每毛份返 1 且暂不计费用和滑点时，十进制毛赔率约为 2.56。模型主胜概率和这个买入价可同屏。对任意结算向量，期望毛兑付为各最终兑付值对模型情景概率的加权和；净收益还需扣除购入和费用。样本中胜负两侧买价合计 1.01，不能把它们直接视作一组加和为 1 的模型概率。仅在做市场概率参照时采用同一时刻、预定义的归一/中点规则，显示缺档及价差。
4. 样本中胜负、全场大小、全场单队大小（两队合并）与让分共 814 个条件，均含 `feesEnabled=true` 及费率 `rate=0.05, exponent=1, takerOnly=true`。官方现行体育类公式为份数 × 费率 × 价格 × (1−价格)。这也解释了为何不可将 0.05 直接当成相对下注额的固定 5%。冻结时间、实际参数、按档/每次成交计费、费用舍入及最小单位、实际扣费资产须同交易所依据相符。沿用仓库的正式和研究费率登记，并审核是否允许该 NBA 合约的范围；缺参数或缺适用条款记为正式费用待核，仅提供明确标记的研究估计。不要套用 `takerBaseFee` 替代完整费率或假设所有历史 NBA 市场免费。[费用定义](https://docs.polymarket.com/trading/fees) · [正式费率登记](../../src/polymarket861/fee_registry.py)

## 采集、回测和验收

- 单独建立 NBA 赛事键，映射 NBA 比赛 ID、球队标准 ID、Gamma 系列和赛事/球队/比赛 ID。例中的 Gamma game `20023943` 属于交易所命名空间。用双方、主客、实际赛程版本、时间及赛制消歧，区分临近连续交手、中立场地和杯赛。数据库中按 event → condition → outcome token 建模，单场数百个市场的赛后样本仍按比赛及固定预测时点统计。
- T−24h 建立预览并记录当前市场覆盖，T−60m 冻结主要预测和意图；若另设临场或 T−15m 研究窗则独立计分。对未来仅开胜负的比赛做增量发现，临近窗口优先核对两支球队的全场单队盘。记录每个家族从首次发现到实际可买的时差。封存时按事先冻结的择线规则选择一条线，例如当期有效、符合深度/价差门槛的 consensus 合约，以数值最小的市场 ID 解同分，保存其他线用于描述。盘口稀薄的时点照样出体育预测并标记无价，后续价格不能补填。实际开球以可验证首个跳球/比赛动作或原生开赛状态和收件时刻核对，开赛后的新消息只能用于赛后归因。
- 生产采集将 11 场的四个主要家族、每家族一条线和两侧令牌作为批量请求优先级最高的一档，共 88 个令牌；让分加 22 个。27 日 4,144 个条件全部按两侧轮询则多达 8,288 个令牌。轮换次要线，独立记录批次、过期、429、超时、深度及断线重连；在同一主机压测一个比赛日，确认没有挤占足球固定窗。实际每批最大数、频率和限流以接口实测及官方当时上限为准。[批量簿接口](https://docs.polymarket.com/api-reference/market-data/get-order-books-request-body) · [频率限制](https://docs.polymarket.com/api-reference/rate-limits)
- 历史比分可评估预测得分。只有相应日期真实收集的同条件、同线、同侧规则与赛前深度、费用、执行口径及最终代币兑付齐备，才计算盘口回放、收盘差与扣费收益；成交价历史不重建真实买一卖一和深度。所有无盘口、无成交、条件改动、爽约窗口、延期及金额部分执行均列分母。先报告赛程→挂牌→有卖盘→合格配对→模拟成交→最终兑付，各层按东部比赛日、玩法与球队汇总。
- 验收反例应包含主客和令牌次序颠倒、同日相同简称、新旧赛程、重复 `consensus`、盘口只一边有报价、`acceptingOrders=true` 但空簿、两份二元簿错配、改线后 condition 不同、整数平线、加时翻盘、中止后已定/未定分流和 50/50 兑付。UI 同时显示知悉时刻、两次盘口、适用规则、资格及原因。自动化只抓资料、校验和纸面记账，沿用项目现有赛前持有至兑付流程。



## 行情用途与第三方历史档案

官方研究指南提供 Gamma 和 CLOB 的公开读取方式。国际站条款对专业资本市场主体及行情分销商的访问、以及面向这些主体的转授权、分发和商业利用有专门限制，同时涵盖原始与衍生数据。本次小样本用于核查可行性。部署时登记访问主体、用途、适用条款版本，分别核准内部研究、本机看板、外部公开展示或行情转发；样本附件不另授行情分发权。同步保留平台终态和赛事标签的不同出处。[Polymarket 研究指南](https://institute.polymarket.com/data) · [国际站条款](https://polymarket.com/tos)

第三方 PMXT 的历史订单簿可列入仅供验证的候选。历史开发先查归档版本、免费获取和上游用途，取一个已知 NBA 条件的两个令牌及一小时区段，小范围验证初始全簿、增量连续性、两种时钟、漏档和过期；中断后不可延续旧深度。满足条件的区段可做“第三方历史簿技术回放”，不能标为本机赛前实收、真实成交或完整历史。此次未验证该档案对 NBA 的逐令牌覆盖。[归档技术说明](https://archive.pmxt.dev/docs/v2-data-overview)
