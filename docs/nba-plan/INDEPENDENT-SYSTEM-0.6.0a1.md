- 分别从基线与候选独立运行足球正式 `forecast release-baseline`。固定八份 OpenFootball 输入、2021/22 至 2025/26 的 1,900 场与 190 轮，含训练输入、每场核心概率和大小球输出的压缩档字节完全相同，SHA-256 为 `f08b88e99499094df2668b25ce7cf4c69ec24ad6fb493cbdee37def8e90fc759`。B0–B3 的八个签核摘要与基线一致。整包来源摘要反映发布版本变化。
- 在独立 venv 安装由 `60c1a2d` 实际构建的 0.5.0a4 wheel。对新建和已升级的 NBA 根分别运行旧版 `pm861 jobs status`、`pm861 fixture list`，四次均退出 2，路径及文件内容无变化。随后 NBA 库成功建表、写入及读回。反向测试中，NBA 拒绝既有足球库，足球文件哈希保持一致。旧足球任意路径的文件导出仍由部署账户的 0700 私有目录提供隔离。
- 核查了足球推荐、历史手工选单、实收盘口账本、归档和微信通知路径。外部赔率缺少有效登记时，三个抓取入口都在 HTTP 之前停止。核对了1,745 场合并样本的校正系数和研究摘要，校正后的概率确实进入候选限价。经过本机原生双时点证明的模拟成交及兑付可重放，更改原买盘后无扣款。NBA 使用自己的数据与球队模型，足球账户对照中的真正新仓触发本地替身一次，NBA 活动触发零次。
- 独立构建并安装候选 wheel。以随仓离线提供方运行实际 `pm861` 控制台，空库看门狗退出 1，市场、赛程和预测三项完成后健康退出 0，T−60 成功封存 N0、N1、N2，`paper_positions=false`。审阅了 NBA 四套用户级 systemd 服务及计时器、足球独立解释器绑定、三 Python 版本 CI、旧 wheel 误指检查与 Ubuntu 服务验收脚本。静态绑定检查覆盖 100 个包属性或导入，Ruff、赛区边界和配方引用检查均通过。
- 在最终 Git 归档运行 143 个针对性用例，其中 NBA 70 项全部通过，另外 73 项足球与发布回归中 72 项通过、1 项因宿主不能创建 Unix datagram socket 而跳过。主要模块包括 NBA 数据、盘口、模型、两级目录保护、时间窗、评分与报告，以及足球盘口原件、纸面账户、微信过滤、看门狗与配方稳定性。

## 签署边界

三种免费数据账号在本次开发现场均无已认证业务回执。原始盘口重放取自窗口外观测，无前向业绩、球队相对盘口优势或 NBA 收益可由此推出。首次在同机实际部署、至少 14 个比赛日的同窗配对、足球各进程的限流与资源占用，以及六笔既有足球持仓的生产原件和微信实际送达，均需现场证据。两项定时任务可能在同一窗口先后完成，封存瞬间已收到的价格才计入配对，晚到同窗价格单列。本地安装测试使用可控数据，原生 Ubuntu 服务的运行结论以托管 CI 实际结果为准。

本次独立证据包括 `probe_rules.py`、`probe_deadline.py`、`probe_commit.py`、`probe_seal.py`、`probe_isolation.py`，以及基线和候选各自的五季报告、安装命令结果和定向测试日志。采集、资金与通知验证都使用研究原件或临时目录，未连接生产账户或发送真实微信。
