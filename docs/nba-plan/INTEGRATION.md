## 数据目录与接口契约

以独立 `NBA_STATE` 保存 `nba.sqlite3`、允许留存的原件、模型快照、研究工作区和 NBA 自己的模拟账。新初始化写入 `sport=basketball, competition=nba` 与格式版本。可用 `pm861 --data-dir "$NBA_STATE" nba …` 操作。服务的环境文件、互斥锁、PID、端口、备份清册及令牌预算独立。看板可在原足球首页提供导航，由只读连接展示 NBA 状态。有权限的运行服务承担采集，打开看板不会发起第三方请求。

| 版本化对象 | 最小字段和一致性要求 |
|---|---|
| 赛程与赛果 | 内部比赛 ID，加赛季、阶段、场地、主客、计划开球、实际开球证据、供应商 ID 与版本。日期+队名仅作候选关联。改期沿用经核实的比赛身份，双重身份须挂起。保存节次、常规时间、每次加时、官方终场及独立的市场兑付事件。 |
| 球员与球队 | 稳定球员 ID、队伍和名单有效区间、原供应商 ID、交易生效日期、位置、来源和首次收件。双向合同/下放召回分版本；同名或绰号碰撞不可自动指派。比赛日的所属队随当时记录重放。 |
| 来源与事实 | 来源条款版本、免费层、允许的自动获取/缓存/存储/提取/建模/展示/再分发、可信等级及撤权时刻。事实记录来源链、发布时间、版本/修改时间、HTTP 首次完整收到和本机登记时间、适用比赛、确认级别、撤回或替代关系。保留原件受限时只存授权允许的字段与出处，并下调依赖原件重放的证据等级。 |
| 预测与市场 | 比赛与赛程版本、预登记时点、模型/新闻规则/数据清单摘要、训练截止、封存时刻与各玩法概率。报价另记条件、代币、选择、分值、规则版本、是否含加时、收件、价档、深度和费用资格。将原始预测、修订评分与结算事件各自追加留存。 |
| 运维与回测 | 作业键由赛事、比赛、赛程版本、时点、任务和配方组成。登记应采事件、尝试、故障和补采结果。用唯一约束及事务保证两个 worker 同时启动只产生一份有效封存或纸面意图；同一市场在连续价格采样时另有独立收件 ID。 |

研究按截止时间同时核对已收到、已登记、当时许可、赛前状态和当时的球队归属。编辑旧新闻保留新版本的首次实收时间。赛后补入的旧报表进入历史重建轨道。模型输入先筛证据，再按版本绑定，迟到资料无法覆盖旧预测。相同网页的十次转载只登记一次独立事实，其余保留来源关系。

## 采集、故障和数据根治

1. 赛程更新生成各场应采窗口，并以 IANA 时区保存场馆本地日和联盟比赛日，比较与持久化使用 UTC。队名、日期或同城场馆变化须由稳定赛程 ID 和可验证版本确认。旧赛程接近开球时发生迟到改期，要核对原开球前是否有可用的取消/延期证据。
2. 已获准接入的全联盟伤停来源，每个版本只取一次，然后分发给涉及的比赛。NBA 官网 PDF 当前仅作人工调查参考。赛程、历史档案、全队名单、新闻、盘口、终场/更正分别记录新鲜度。以来源公布频率和免费配额计算下一次到期，固定窗优先，让历史补采让出配额。遵守 `Retry-After`，429 或源退化显示下一次可重试时间。同一机器共享 NBA 与足球的上游额度时按域/免费账号总额限流；NBA 可用分额不足先降频，不能挤掉现有足球固定窗。
3. 按主计划登记固定赛前时点；可变资料变化只触发重新计算相应场次的情景。同一模型、玩法与输出不变时写轻量证据，评分分母按比赛和时点去重。联赛共享源故障产生来源级降级，单场身份冲突只挂起该场受影响输出。市场缺盘时仍可完成有数据的纯模型预测。
4. 采集请求、解码、原件校验和模型计算在长写事务外进行。短事务内复核赛程版本、授权和当前时钟再落盘。若已开打、已超过固定窗或可用时间不清楚，记 `missed` 或 `withheld` 及理由。重启只重放仍在有效时段的任务。确定补赛与已开始后续赛使用不同任务规则。
5. 事故按「源与字段、出错版本、影响场次」归并。发生先发人名映射错误、交易后旧名单、PDF 栏位错位、队伍对调、加时漏计、比分撤回等，自动隔离受影响字段，查出全部关联训练样本、评分和当前活跃预测。原封存保持可读并标示撤回原因。新信息发布有时点的更正，重算派生统计和当前可用预测，保留更正前后的版本与差异。以独立原件或已核对人工纠正进行回放，在干净样本和原故障夹具上通过后恢复适配器。

例如，同日伤停报告将一名刚交易的球员列回旧队，而后到的球队修订确认新队。系统先记录两个报告及实际收件时间，隔离这条人物映射、保留其他球员输入，在修订到达后重算新队仍未截止的情景。已封存的旧预测标注数据事故；回测必须能按修订前后的两个截止时刻分别重现结果。

## 本地 Codex 的迭代范围

沿用 `maintenance.tick` 由轮报、来源状态、事故及定期免费源发现派单的思想。现有 `research_workspace` 的模型验证会走足球配方与轮次，篮球需增加领域适配器，使用 NBA 的同场配对、日/周分组和候选记录。新闻提取模型与改代码/找来源的 Codex 作业分开运行。新闻正文属于输入数据，交给抽取器时只接收结构化字段、证据位置、实体 ID 或弃权；正文中的指令不能转成工具操作。[维护入口](../../src/polymarket861/maintenance.py) · [本地提案与验证](../../src/polymarket861/research_workspace.py) · [现有新闻提取器](../../src/polymarket861/news_local_ai.py)

| 触发 | Codex 交付物 | 激活条件 |
|---|---|---|
| 某来源持续失约、字段变更、错队或权限变动 | 根因、故障样本、影响清单、适配补丁、旧版原件重放和纠错报告 | 样本在新旧解析器的差异可解释，收费/受限/身份不明的字段保持隔离，失败可回退。 |
| 每周来源缺口 | 新来源候选及上游身份、获取方法、免费配额、条款日期、用途矩阵、样例摘要、依赖与替代关系 | 核实免费可长期使用及具体字段权限，完成小流量影子采样，与现有来源对照。页面转载同一数据源不形成第二个独立确认。 |
| 赛日/周报显示校准漂移或伤停组欠佳 | 可证伪的假设、特征/权重差异、版本、消融及预注册方案 | 按冻结验证协议验证，通过独立复审并具名登记生效时间。按旧配方读回旧封存。 |

用户启用本地 Codex 后，由受限工作区产生候选和补丁。传给维护代理的材料按许可脱敏，排除在役密钥、未揭盲样本与生产写权限。预算和并发槽可配置；未配置模型或代理超时时，采集、基线、评分和运维报告继续运行，作业留在队列。只将已揭盲历史、正常运维指标及明确标为探索的周报传给维护代理。正式配对比较留在隔离数据区，到登记终点解封，生产修复及另开候选均记录生效时刻。重复事故只分配一次，可安全重试。来源和模型有单独的生效指针，撤回数据源不应改变无关基线。

## 上线与复验工单

| 工作包 | 交付和可观察的通过条件 |
|---|---|
| 领域和 CLI | 拟交付 `nba init`、`sources`、`collect`、`run`、`status`、`watchdog`、`forecast`、`backtest`、`report` 等入口，具体参数随接口冻结。独立干净目录端到端走通；NBA 写命令碰到足球目录须给出原因并保持足球库校验值不变。 |
| 调度和看板 | 拟增 `/nba` 赛日及单场视图，列时点、胜负/总分/主客队分、模型和市场可用性、限制、球员状态依据、信息最新时间及评分版本。健康页分「进程存活」「关键输入新鲜」「实收窗口」显示；空库、停进程、上游故障均能从 CLI 返回可区分状态。展示时各玩法单列覆盖分母。 |
| 备份和独立服务 | 首选与现有项目一致的 Linux + CPython 3.12/systemd 部署，NBA 单元显式启用并指定专用用户目录与配额。用 SQLite 一致性快照、资产清单和哈希验证还原至新目录。恢复后旧封存和原件可按摘要读回。模拟终止、暂停、超时、429、开球前改期与接近截止的写锁，核对告警、恢复及漏窗记录。停用 NBA 或回退 NBA 服务不重启在役足球。 |
| 发布隔离 | 足球原有 Python 3.11/3.12/3.13 回归、引用检查、真实 Ubuntu 服务和原封存读回齐备。对比基线的足球 B0–B3 配方和新闻规则摘要，并执行英超五季 1,900 场/190 轮同输入对照。新增包文件会改变整个安装包的运行来源摘要，应单列。若出现足球配方变化，调查引用并走现有同库比较与具名签批流程；NBA 发布记录本身不能授权变更足球模型。 |

## 对现役足球模拟账户与通知的隔离验收

在本轮调研期间合入的 `60c1a2d` 包含五大联赛七天推荐列表、10,000 模拟美元共享账本、仅新开仓通知的 Hermes 微信任务。足球推荐用 `verified-football-recommendations-v1` 和足球留出季校准。账户服务有成功运行后的通知触发器。通知器依据账本里同时标记为 filled 的仓位与决策筛选，联赛名映射未识别时仍可显示原字符串。仅添加一个“篮球”标签不足以防止误通知。[部署交接](../five-leagues-0.5/PAPER-AUTOMATION-HANDOFF.md) · [推荐账户契约](../../deploy/paper-automation/five-automation/recommendation-feed/README.md) · [足球账户单元](../../deploy/paper-automation/systemd/system/pm861-paper-10000.service) · [开仓通知过滤](../../deploy/paper-automation/five-automation/weixin-recommendations/notify.py)

给 NBA 分配独立的研究资金、账户标识、文件路径、策略校准及进程身份。NBA 服务不生产足球的 feed、positions 或 decisions，不调用足球服务的 ExecStartPost。共存测试使用生产布局的临时副本及本地发送计数替身：提前记录足球现金、决策、推荐及通知去重表的摘要，模拟 NBA 一笔成交、重启、兑付各一次，验证上述摘要无差异、发送次数为零。同一测试再给足球账户一笔满足现行条件的新仓，发送替身应恰好收到一次，验证计数确实生效。若将来另行启用篮球通知，还须显式指定账户和接收配置，按运动、账户、仓位与实际成交回执去重。
