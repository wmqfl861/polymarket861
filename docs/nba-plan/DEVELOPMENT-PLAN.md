# NBA 扩展开发计划与验收工单

> 2026-11-28 实施范围及生效顺序见[审核后开发计划](REVIEWED-DEVELOPMENT.md)。本页保留 11 月 27 日送审设计及调查依据。

提审日期为 2026-11-27。以送审时主分支 `60c1a2d` 的足球运营脚本和 `0.5.0a4` 预测软件为基线，目标是同一项目内能长期运行的 NBA 赛前预测、消息驱动研究和持有至结算的模拟账。审核通过后按以下顺序实施。表中人日是工程估算，观察比赛和取得前向证据的时间另外计算。[总蓝图与六份调查](README.md)

## 第一版的交付边界

1. 面向 NBA 男子 30 队。常规赛四项概率从一份联合得分分布产生。杯赛改变赛程时重建当时可知版本。特殊阶段在资料和验证充足前独立登记、展示资格，不混入常规赛报告。终场结果预测与 Polymarket 兑付各有原件。
2. 默认在 T−24h 给出预览、T−60m 保存主预测与纸面意图、T−15m 单独保存临场研究。开发时建议在各截止前 5 分钟准备输入，预测以不晚于截止的实际持久化时刻为准，展示实际提前量。每条未来窗口及执行延迟在正式研究前用试运行数据固定。比赛已开始、来源冲突或截止已过就记漏窗。持仓只在有合约、执行簿、经核费率及剩余预算时模拟一次，持有到交易所实际兑付。
3. 交付完整的数据、情景、AI 抽取、概率和评分路径。首发覆盖、球员可量化影响、新闻增益及净收益分别验收。任一联赛日或某队缺资料时可以从 N4/N3 回退到 N2/N1，并保留原申请层次、原因、字段和覆盖数。未知状态不得改写为“健康”。
4. 保留赛程、比赛结果、固定时点、新闻版本与球员效力区间；支持历史回放、逐比赛日暂报、周报、赛后修订和根因修复。使用项目已有本地 Codex 进行候选来源发现、条款/字段变化识别、适配修复和模型比较。来源、模型、协议、足球配方各自版本化；不开实盘下单通道。

三条并行线可以在 A 后同时抢收赛前资料（B/C/D）、开发历史模型（E）和做验证/运维骨架（G/H）。先固定契约、标识、时点和夹具，再由不同代理按模块工作。合并时由一位集成人核查输入版本和输出分母。估算合计 34–54 人日，按 3–4 条有效并行线预留约 3–5 个工程周，假定免费账户与数据能够按预期开通；镜像许可、前向试验周期和真实结算不能靠增加代理缩短。

## 工程上线和研究晋级的顺序

- **里程碑一，免费数据能否开工。** 在正常免费账户上对首选和备选各做一次能力盘点。按每个来源列可取得的赛季、30 队中有数据的队数、分页、稳定 ID、单场/球员字段、首次和最后实收时间、额度及条款。至少包括过去一场、有赛程但未开打的一场、交易或改期样本。表要显示按端点成功/失败；没有密钥的调查不登记为实采通过。球队基准通过即可推进；球员或新闻分支缺料就保留适配和回退，列出具体缺口。[数据调查](DATA-SOURCES.md)
- **里程碑二，足球不受影响且篮球可历史回放。** 建议使用 2018/19–2020/21 暖启动、2021/22–2024/25 滚动开发和 2025/26 一次留出。单一来源起始季较晚，按支持的季段重新登记可比交集，再看模型表现。出版物/终态比分只能支撑技术回放；未知历史新闻以缺件入账。保存训练输入、留出前提交、参数、报告和环境。只对当前窗口可核实的数据等级声明能力。[模型设计](MODELING.md) · [验证方法](VALIDATION.md)
- **里程碑三，第一版的实际运行。** 建议连续至少 14 个有比赛的日子，统计每个联赛比赛日、队别和窗口的计划、实收、缺失、请求延迟、HTTP 429、磁盘与实际封存。主机故障、网络中断、隔夜比赛和更正恢复各演练一次。在当期确有盘口时按指定金额报告可成交覆盖及独立兑付数，零笔就写零。看板可交付研究使用；正式胜方及大小分各自等待验证。[集成和部署](INTEGRATION.md)
- **里程碑四，新闻是否值得采用。** 先开展不计为正式试验的盲标、覆盖/功效试运行，随后冻结终点、开始时间、样本资格、模型和来源口径。审核后主比较是同一场 T−60m 与 T−15m 各自 N4 相对 N2 的胜方 Brier 差和收盘平方误差差，四项校正。N3−N2 与 N4−N3 拆分贡献。三个大小分分布指标另列次终点。到点按预登记统一揭盲，报告比赛与周分母、不确定性、缺件/弃权和实用效应；证据不足可继续积累新登记样本。历史赛果比较、预测质量、实际可模拟买入、收益分开批准。[新闻试验](VALIDATION.md)

**特殊赛制的后续验收。** 初版记录的杯决赛、附加赛、季后赛可生成独立研究预览。推进到正式使用前分别重测中立场、系列赛重复对手、每轮主客转换、轮换缩短、淘汰战休息时间及该阶段的合约条款。队伍只打一次的杯决赛样本尤其稀少，可采用透明的跨阶段收缩并报告宽区间。样本不足的阶段维持情景/研究显示。季后赛另按系列赛/轮次出报告，累计到足够的独立赛季后才比较专属模型。

## 采集预算与降级顺序

比赛目录按未来窗口渐进发现，缓存球队/球员和历史对照，按身份和版本幂等。按域名共享限速器、遵守 Retry-After，429 退避期间优先保障临近截止的任务。有条件抓取和按需批量读取，轮询频率要用真实响应和额度验证。额度优先分配给赛程变更、终场、固定窗口的伤停/名单以及关键盘口。远期新闻和附加分数线可降频，收件迟到、报价过期、盘口只有买方等原因进入当日分母。

以本次抽样的 11 场做容量估算。每场胜负一份、全场大小一条、两队各一条，需检查 44 份合约、88 个令牌。假设三个时点各取一次完整双边簿，另在主决策后取一份执行簿，共 352 个令牌快照；这是批量前的业务数量，实际请求数取决于每批限制、重试和新增盘口。同窗比较多线时在额外预算内独立取样。每日报告平均压缩字节数 × 实收快照数加索引/WAL，按实测 95 分位日流量规划空间。试运行期间记录新闻轮询和 AI 的每条耗时；输入未在截止前处理完即标示弃权。[市场账和样本](POLYMARKET.md)

## 交给 Claude 的审核任务

| 审核问题 | 若未通过，开发怎样调整 |
| --- | --- |
| 正常免费档是否实能提供所需统计、伤病及用途？对未来有无时点留痕？ | 保留球队比分产品，缩小球员层可报范围，优先做实际赛前收件。不能用当前名单反推历史或通过镜像扩大权利。 |
| 存在 NBA 数字 ID 对错队、赛程更正后复用旧开球、单队大小与球员道具或半场错配的反例吗？ | 在 B/C 加入失败夹具、重新核定受影响合约或源；未知映射不产生模拟持仓。 |
| N3 与 N4 是否真正只差增量新闻？高流量球队、无消息比赛、交易前后的球员是否被等权及正确对待？ | 收紧可用字段、重复事实去重与同场配对定义，更新尚未登记的试验草案，并在看结果前冻结。 |
| 何时允许出概率、声称有预测增益、建立纸面持仓、声称有经济优势？ | 分别依据模型有效性、前向终点、成交与费用、完成兑付的独立证据。报告需能给出“尚无足够数据”的结果。 |
| NBA 的运行故障、维护代理和数据迁移会不会改变足球签批或历史回放？ | 缩小跨域复用，增加隔离测试。冻结旧足球安装做对照，按运动单独禁用或回滚。 |

审核的预期产物是一份逐项意见及优先级，最好附可复现数据或反例。需优先决定的是数据源准入试验、全场合约加时适用证据、N4 增量试验的设计和冻结顺序。这一提交不触发部署、研究登记或实盘交易。
