# polymarket861 英超预测系统 · 第一版蓝图

设计稿 · 2026 年 11 月 25 日 · 供讨论、开发和验收使用

## 1. 首版要交付什么

每场英超生成赛前比分概率，覆盖胜平负、全场进球大小、主队进球大小、客队进球大小。投注试验只采用选定 Polymarket 站点当时可成交的价格，赛前模拟买入，持有至合约结算。比赛数据、新闻、天气和行情的数据采购预算为零。本地 Codex 沿用已有配置，可持续维护整个系统。

| 你在系统中能做什么 | 首版验收时应看到什么 |
|---|---|
| 打开一场比赛 | 四组概率、各条线的公平赔率、实际买入成本、阵容与伤停、关键证据、模型版本，以及模拟买入或跳过的原因 |
| 查看一个数据源或一个字段 | 最近一次应更新和实际更新的时间、当前覆盖、延迟、来源、适用时点、实际用法、备用来源，以及最近一次变更 |
| 追查一个输入错误 | 原始证据、受影响的球员和比赛、错判由哪一环产生、修复记录、重算结果、能拦住同类错误的测试 |
| 查看一轮联赛 | 四项概率评分、市场和基线对照、实际覆盖、扣费后模拟收益、未完成场次、错误归因和下一轮要验证的假设 |
| 检查一次 Codex 改动 | 原因、代码和数据版本、使用说明、独立验收结果、和旧版本的差异、是否已启用、回滚位置 |
| 查看并行任务 | 各子代理的职责、依赖、进度、阻塞原因、产物和验收结果，能看出哪个环节决定本轮完成时间 |

## 2. 每场比赛怎样产生预测

**统一比分模型。** 以球队攻防强度、主场效应、近期状态、对手强弱为基础，用带时间衰减和低比分修正的 Dixon–Coles 模型建立可复现的基线。加入人员、赛程和比赛条件后，得到主客队各进球数的联合概率。胜平负按比分比较汇总，全场大小按双方进球之和汇总，单队大小按相应球队进球数汇总。比分尾部也计入概率。验收检查概率之和、主客方向和不同进球线之间的单调性。[Dixon–Coles 原始论文](https://doi.org/10.1111/1467-9876.00065)

| 输入 | 进入模型的方式 |
|---|---|
| 球队攻防与近期状态 | 调整对手强弱、主客场和历史比赛人数差。结合比分、射门、机会质量，按样本量将升班马和新援估计向合理的联赛或位置平均值收缩。 |
| 球员与阵容 | 记录资格、转会生效日、首发概率、替补人选、预计分钟和位置。前锋看创造与获得机会，门将看面对射门的质量，中后场考虑搭档。按近期常用阵容估计替换的边际影响，避免长期伤情被重复扣分。 |
| 伤停、红黄牌与新闻 | 区分缺阵、出战成疑、伤愈限时、预计首发和正式首发。按赛季及赛事核对停赛和已服场次。模型对未定人选组合加权，消息更新时只重算受影响的组合。历史红牌用于区分十人与十一人阶段，本场牌数只能在赛前估计风险。 |
| 赛程、天气与比赛环境 | 按球员实际出场分钟估算负荷，结合休息日、欧战、旅行、换帅、场地变化和开球时的天气预报。新闻须能追溯到具体事实。每类附加因素用后续比赛检验是否改善预测。 |

**时间和投注口径。** 默认在开球前 24 小时封存初判，前 60 分钟封存用于本轮主评分和模拟买入的预测。正式首发发布时可另存一版。若首发在前 60 分钟之后才被系统收到，晚到版本单独评估。两个默认时点及主评分协议可在新一轮实验开始前调整。比赛改期保留旧赛程和快照，新预测绑定更新后对应的开球时间。

**模拟成交。** 给比赛、合约、时间范围、球队、大小方向和进球线建立对应关系。每次存同一时点逐档卖价、可买数量、时间戳、费率和结算规则版本。按模拟金额逐档计算可成交份数、均价与手续费，回报以实际份数和合约最终兑付计算。报价过旧、没有对应合约或无法核实规则时，仍给足球预测并标记交易状态。同场不同盘口按每种比分的合计损益限制总风险。取消、腰斩、改期和特殊兑付分别记录足球赛果与合约结果。[Polymarket 订单簿](https://docs.polymarket.com/market-data/prices-order-books) · [费用](https://docs.polymarket.com/trading/fees) · [结算](https://docs.polymarket.com/concepts/resolution)

## 3. 让数据源和“怎样使用它”一起迭代

每个来源要有一份可供程序和 Codex 读取的使用说明，写明覆盖赛季、赛事、接口或文件、字段含义与单位、主客顺序、阵容确认标记、预期更新频率、事件与发布时间、系统首次收到时间，以及已验证的用途和备用源。说明随适配器版本保存免费条件、允许的用途、文档地址、样本和已知缺陷。免费条件改变时，停用受影响的入口并切换到已验证的免费备源。

| 环节 | 系统行为 | 证据与产物 |
|---|---|---|
| 发现新增来源 | 按覆盖缺口检查免费公开目录、提供方公告、版本更新及现有来源引用。例如发现单队进球的射门数据有空缺，就定向寻找补充。 | 候选来源、解决的缺口、免费条件、实际英超样本、是否与已有源共享上游 |
| 监测更新 | 在本应变化的时间窗检查最新有效比赛、发布与到达延迟、字段结构、单位、枚举、主客顺序、异常空值。临开球名单的要求高于已经完赛的比分。 | 健康状态、最后成功时间、落后场次、变化样本。接口返回成功但内容冻结也会告警。 |
| 试接和验证用法 | 候选在相同比赛、相同决策时点旁路运行。对比覆盖、及时性、准确性、重复率，并单独比较加入该字段前后的预测表现。 | 分字段结论。例如某源可作赛后球员分钟主源，其赛前阵容只有正式确认后才能作首发证据。 |
| 切换、降级、恢复 | 按字段选择主源与备用源。明确的格式变更可自动修复并重放。语义不明的字段先隔离，切到验证过的来源，或使用已验证的缺失值策略。 | 版本差异、切换原因、回滚点和受影响的比赛。恢复前用已知坏样本和近期正常样本验证。 |

每条事实保留上游修订编号或内容指纹，以及它更正或撤回的哪个版本。并行采集可能先收到更正再收到旧包，存储按修订关系选取在决策当时可见的版本。替换 xG 来源前，用重叠比赛核对是否含点球、是累计值还是每 90 分钟值，并比较尺度。定义不兼容的指标独立建特征。

首批可核查的免费来源如下。逐赛季覆盖、到达延迟和许可适用范围都应进入接入报告。

- 足球赛果和比赛统计用 Football-Data 的免费英超 CSV，赛程和赛果可用公共领域的 OpenFootball 交叉检查。[Football-Data 英格兰数据](https://football-data.co.uk/englandm.php) · [OpenFootball 英格兰](https://github.com/openfootball/england)
- 球员、xG、牌和阵容优先抽样 PitchAPI。文档说明可以使用免费密钥，阵容带有确认状态。要实测它在哪些比赛能赶上决策时点。[PitchAPI 文档](https://pitchapi.dev/)
- 新闻用 GDELT 免费索引发现，再按来源核对事实。转载聚合到同一条原始消息，报道冲突保留各自证据。文本模型只提取当时可见原文中有依据的字段，保留证据定位，防止模型凭已知赛果补写历史原因。新闻原文按来源允许的方式使用，英超伤停和停赛公告可作核验。[GDELT 数据](https://gdeltproject.org/data.html) · [英超伤情](https://www.premierleague.com/en/news/4450606/latest-premier-league-player-injuries-club-by-club-news) · [停赛说明](https://www.premierleague.com/en/news/4425344) · [英超使用条款](https://www.premierleague.com/en/terms-and-conditions)
- 天气按球场位置和预报发布批次匹配。行情从 Polymarket 公开赛事与订单簿读取，按站点和市场分别归档。[NOAA GFS](https://www.ncei.noaa.gov/products/weather-climate-models/global-forecast) · [Polymarket 赛事发现](https://docs.polymarket.com/market-data/discover-markets)

## 4. 错误输入怎样纠正并防止复发

1. **发现与隔离。** 数据入库、预测发布前、赛后对账各检查一次，也支持在比赛页直接标错。识别错队、同名球员、错误比赛归属、重复新闻、陈旧盘口、预计名单误作确认、时区错位等。关键字段异常必须在下一笔模拟买入前隔离，依赖它的新预测重算或降级。若影响投注方向且来不及核实，该场暂停新增模拟单。逐次记录发现、隔离、修复和恢复时间，纳入轮报。
2. **追出影响范围。** 每条预测均能沿着“证据版本、字段、球员／比赛、特征快照、模型版本、预测和模拟单”反向查询。确认是单条错误、整个接口的解析偏差、上游更新，还是一条原本正确但后来失效的消息。模型一次猜错不构成错数证据。
3. **修到产生错误的位置。** 给数据补上更正版本和证据，修复映射、解析、字段用法、去重或来源选择。确定性错误可以自动修复。有矛盾的消息保留不同情景与可信度，直到独立证据足以定案。
4. **验证关闭。** 用真实触发案例新增回归测试，重放受影响日期，核实同类坏样本被拦、正常样本能通过，并观察后续批次是否复发。外部提供者持续出错时，切换依赖并监测其恢复。问题单记录原因、修复版本、受影响预测数和复查结果。

纠错范围还要追到训练集、校准器和已经上线的模型。若含点球的 xG 曾被当作非点球 xG 参与训练，修正当前比赛输入仍会留下错误权重。系统应标记受影响版本，重训或回退到经验证版本，再重算仍可行动的比赛。

**首版必须演示一个真实形态的故障。** 接口返回的十一人名单完整，但字段 `confirmed=false`。旧适配器把它当正式首发。系统应定位所有被污染的伤停权重、单队进球概率和模拟单，修正适配器、重算仍未开球的预测，并通过“完整预计名单”和“正式名单”两条相反样本。原来在赛前真实发布的版本继续作为当时表现的审计依据。用纠正输入重放的结果在另一列展示。若更正的是官方赛果，则发布更正后的成绩单和版本差异。

## 5. 建模后先做历史回测

赛前行情和新闻快照可以在建设期开始留存。模型建成后的首项验收是历史回测。回测报告完成后，才启用正式的逐轮前向模拟。

| 实验 | 做法 | 可以回答的问题 |
|---|---|---|
| 历史赛果回测 | 建议先用 2021/22–2023/24 开发，2024/25 选模型和阈值，2025/26 首次独立盲测。按真实赛程滚动，同日比赛按实际时间判断哪些结果当时可用。标准化、选特征、校准都只用各训练窗口。 | 四类概率是否优于简单联赛频率或只看球队的基线，哪些球队和进球线误差大？ |
| 赛前信息重放 | 每场只读取截止时点可证实已经公开的阵容、伤停、天气预报和新闻。记录档案来源。已运行过的比赛用系统首次收到时间。缺少当时版本的字段标记缺失，历史赛后确定的阵容只可用作核对标签。 | 人员和新闻能带来多少增益，采集延迟损失了多少？ |
| 历史投注回放 | 相同站点、合约和时间下重建卖盘、数量和费用，按真实规则结算。只有价格曲线的场次可做价格研究，收益统计只纳入能核实成交条件的样本。 | 在可执行样本中，优势是否覆盖价差、深度和手续费，覆盖偏向哪些比赛？ |

输出逐场预测、按玩法和赛季的评分、与基线和市场的可比样本、数据缺口、覆盖分母、模拟净收益、回撤及复现配置。分别标注“赛前可证的档案回测”和“系统当时实际运行”。缺少完整历史订单簿时如实列出能回放的场次，不生成替代价格。并行候选共用一份盲测协议。先登记候选数量、版本、参数、指标和揭晓时间，独立评分程序在全部候选锁定后一次披露结果。开发者或代理看过成绩后，该批比赛转为回归测试资料，改出的新版本用尚未揭晓的比赛验收。[滚动时间回测方法](https://alan-turing-institute.github.io/tea-techniques/techniques/rolling-origin-evaluation/)

## 6. 每轮联赛的成绩单

按英超官方比赛轮次归属聚合。每场赛果落地先更新进度，延期和待裁定比赛列为待补。该轮比赛均有最终体育状态后发布赛果定稿。Polymarket 尚未兑付的合约单列，全部结算后更新模拟账本。补赛、赛果更正、任务重启和重复通知均生成可追踪的更新，按比赛与版本去重。

**建议采用一个易读的 0–100 分主指标。** 默认四项是胜平负（三种结果合为一项）、全场大 2.5、主队大 1.5、客队大 1.5，在实验开始前固定。系统仍为其余挂牌进球线输出概率和分项评分。固定四项避免某一轮因多挂牌十条相似盘口而左右总分。

- 胜平负损失为 `0.5 × 三个结果的 (预测概率 − 实际指示值)² 之和`。实际发生的结果记 1，其余记 0。
- 每个大小球损失为 `(大球概率 − 是否实际开大)²`。同一半球线计一次，小球概率是该线大球概率的补数。
- 单场分为 `100 × (1 − 四项损失的平均值)`，轮次分取各完整比赛单场分的等权平均。每项也分别汇报。所有有正式赛果的合格比赛都在覆盖分母中，漏发单列。存在漏发时标注覆盖不全，总分不得单独用于版本晋级。市场对照与候选对照使用相同比赛和时点。

算例仅用于验算。模型报主胜、平、客胜分别为 50%、30%、20%，最终主胜，这一项的损失为 0.19，对应 81 分。若这场比分为 2 比 0，另外三项大球概率依次为 40%、60%、25%，则损失依次为 0.16、0.16、0.0625，四项合计得分 85.69。这一分值衡量概率误差，实际命中率另列。[Brier 评分定义与取值范围](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.brier_score_loss.html)

同样是“只算了 9 场”，有三种不同原因。若第 10 场尚未补赛，显示阶段报告。若 10 场均完赛、漏发 1 场且其余均分 80，显示覆盖 9/10、已评分均分 80、按漏发场可能取 0 至 100 分计算的全轮范围 72 至 82。若第 10 场只缺盘口而有赛前预测，照常给它打分，只在投注统计中列为不可定价。补赛使用新赛程下真实封存的决策版本，回填原轮一次。

| 每轮同时公布 | 查看内容 |
|---|---|
| 概率质量 | 总分和四项分，其他挂牌线的 Brier 和对数损失，赛前 24 小时与 60 分钟的差异。跨轮画校准曲线，记录每个概率区间的样本数。 |
| 对照与不确定性 | 简单基线、当前正式模型、候选模型和同刻市场。三项市场概率使用同刻可用双边报价中点归一，单队和全场大小使用同线双边对照。披露价差过宽或缺盘的样本。多轮比较按比赛或轮次分组估计不确定性。 |
| 模拟收益与风险 | 覆盖的比赛、可定价合约、模拟笔数、成交金额、手续费、净收益、净收益／累计投入、按一致账户估值口径的最大回撤、同场合计风险。零投入时收益率列为“不适用”。目标是分辨概率改进和价格优势各自贡献多少。 |
| 数据与行动 | 应预测／已预测／待补场数、名单及时率、行情覆盖率、错误条数与影响、修复状态。列出需要试验的原因及下次检查方式。足球赛果和合约的特殊结算分别评分、记账。 |

## 7. 本地 Codex 如何持续维护系统

| 改动类型 | Codex 可以做什么 | 决定是否采用的证据 |
|---|---|---|
| 源与适配器 | 发现新免费源、检查源迁移、修接口、补采、更新字段字典与使用示例 | 真实样本可用，时间与语义核对通过，正确率、及时率或覆盖达到预设要求，可回滚 |
| 数据用法 | 调整哪些字段可作正式证据、回放特定故障、合并同源转载、修复球员映射与备用源优先级 | 复现原错误，异常和正常两类测试通过，受影响范围重算，质量报告可复核 |
| 模型与投注决策 | 调整阵容情景、预计分钟、进球分布、校准、手续费后的入场门槛和同场风险配置 | 冻结指标及阈值，按时间回测，在相同未来比赛并行预测。目标改善、其他关键项在事先约定的容差内，且覆盖和样本量充足 |
| 评测与运维 | 提议改进评分、报告、任务重试和监控，更新维护说明 | 评分规则若改变，建立新协议版本，以同一协议重评旧模型和候选。数据快照、原始成绩和历史账本均可追溯。 |

本地调度程序可在独立 Git 工作目录调用 `codex exec --sandbox workspace-write --json -`。向 Codex 提供已结算的研究样本、问题单和来源使用说明。每次记录假设、代码差异、数据版本、测试、回测和是否采用。候选模型在新比赛开球前提交并封存预测，独立评分程序在赛后执行。发现数据接错可以快速修复，统计策略升级则积累独立样本后自动晋级。Codex 离线或额度暂不可用时，正式模型照常预测，待处理事项进入队列。[Codex 非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)

## 8. 多子代理并行开发与运行

设一个本地调度器，按任务依赖派工。多个子代理可以同时开发不同模块、分析同一份只读快照或验证不同假设。定时采集、概率计算、评分和记账由可复现的普通程序执行，Codex 用于发现资料、研判异常、修改代码和设计实验。并发数、超时和各免费来源的请求频率按机器和服务可承受的负载配置，临开球任务优先于批量研究。[Codex 子代理](https://learn.chatgpt.com/docs/agent-configuration/subagents) · [Git 独立工作树](https://git-scm.com/docs/git-worktree)

| 工作组 | 可以并行做的工作 | 必须等待的输入或验收 |
|---|---|---|
| 数据源与球队新闻 | 各组分别维护数据适配器，检查上游更新、球员身份、伤停、停赛、阵容与场外消息 | 确认比赛实体、字段含义和证据可用时间后，发布版本化输入 |
| 盘口与模拟投注 | 各场并行核对全场及单队合约，采集不同进球线和订单簿 | 入场需要同场同刻的封存预测、有效报价和账户风险检查 |
| 模型与评测 | 在独立工作树和相同输入快照上，同时运行基线、正式模型和候选实验。回测折可并行，各折独立拟合。 | 比较前锁定候选和指标。赛果落地才评分，合约结算落地才入账 |
| 质量与集成 | 独立检查数据泄漏、证据、代码差异、回放和回滚，汇总各组结果 | 共享接口变更有一名集成者负责。通过对应验收后统一发布正式版本 |

每个任务有稳定编号，记录对象、截止时点、快照哈希、配置及代码版本，输出证据、测试和状态。不同任务使用独立工作树或输出目录。调度器为运行中的任务分配有期限的执行权。进程崩溃时可重新派发，过期进程恢复后也不能覆盖已经发布的结果。缓存相同源请求和公共特征，记录排队时间、处理时长、重试次数和模型用量，便于找出实际瓶颈。

各代理可以并行提出模拟订单，由同一账本按预先约定的顺序核对资金、同场风险和同一快照下的剩余挂单数量，在一个事务里完成成交与扣费。每个订单意图和每笔结算都有唯一编号。重试不得重复消耗同一档流动性，期末余额和份数都能按实际成交、费用与兑付逐笔对账。不同候选策略使用独立模拟账户，才可以公平地比较它们各自单独执行时的表现。

**首版并行验收。** 准备相同的代码、快照和随机种子，分别串行、并行跑同一轮，比较评分、订单、最终净值和实际耗时。途中终止一个任务并重新派发，同时注入一次主客标识互换和一条重复结算通知。用 2 比 0、0 比 2 等比分验证盘口映射。错误方向须在成交前被隔离，正常订单的成交、费用、兑付各记一次，恢复后账本和串行基准一致。

## 9. 开发顺序与整体验收

适合先做单机部署。Python 负责采集、特征、预测、模拟和回测，关系数据库管理比赛实体、任务和版本，按日期保存可复用的原始快照与模型输入。界面提供比赛详情、数据源、轮次成绩、错误与修复、实验与版本和并行任务六个入口。每条结论可定位到证据或配置，每次运行可以断点续跑。先约定比赛、快照、合约、预测和账本接口，各组即可并行实现，按下表的依赖顺序做整体验收。

| 同一首版内的建设顺序 | 完成证据 |
|---|---|
| ① 数据源、赛事标识、历史和赛前快照 | 能跟踪免费源新增、停更、字段变化和主备切换。主客别名、夏令时、改期、重复事件和中断补采均有测试样本。 |
| ② 比分模型、新闻和盘口、历史回测 | 四组概率互相一致，能逐场还原输入。实际跑出分季回测和覆盖报告，从全新环境按固定版本可复现到约定的数值精度。 |
| ③ 模拟账本、轮次评分和数据纠错 | 同一轮有正常比赛、延期、补赛或特殊结算时，分别产生正确进度、评分与净收益。演示错误隔离、根因修复、重放和防复发测试。 |
| ④ Codex 迭代、并行候选和回滚 | 演示接入一个新增免费源、修复一种字段语义变化、评测一项模型改动。可重现一次晋级、一次证据不足继续观察，以及回滚后的继续预测。晋级和回滚机制可用预置样本验收，实际模型优势须用独立比赛证明。 |
| ⑤ 多子代理集成验收 | 同一轮串行与并行结果一致，实际耗时分别记录。重复订单、重复通知、乱序旧包、进程中断均可恢复，任务页能追到责任工作组、证据和验收结果。 |

首版交付应附可运行程序、免费来源清单及用法、实际历史回测报告、模拟账本、每轮成绩单、已验证的故障案例和可回退的版本记录。本文给出设计和验收口径，数据覆盖率、模型分数和收益由实施后的实际运行填报。
