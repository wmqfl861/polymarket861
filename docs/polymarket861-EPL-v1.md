## 1.4 球队消息进入赛前比分分布

新消息到达或原消息被撤回时，研究服务重新核对该场比赛的球员证据，按变化追加有时间、前版摘要及概率的赛前更新。赛后比较使用两个预登记决策时点，每场在每个时点只计一次。部署者可用 `news updates` 追踪临场变化，用 `news evaluate` 查看固定配对成绩。

赛季服务根据已登记的英超赛程轮询免费球队消息与当季名单。每个候选事实绑定球队、稳定球员身份、原句、来源版本、发布时间、收到时间和完成识别的时间。报道、传闻、球队确认、否认和更正分别保存。报道目标与本场对不上、同名无法判别或消息相互矛盾时，在覆盖和排除明细中记录。

同一个赛前输入快照产生两组比分概率。B1 以球队历史估计进攻、防守和主场优势，B3 在这份比分分布上用预先固定的位置与消息权重检验球员缺阵假设。两组分别计算胜平负、全场及双方单队大小球。每个比赛时点的预测与新闻证据一起封存。评分同时报告分母、采集覆盖、概率改变的场数、同场分差和按轮不确定性。正式模型切换沿用既有治理。运行和研究口径见[球队新闻操作与评测](TEAM-NEWS.md)。

## 1. 首版要交付什么

每场英超生成赛前比分概率，覆盖胜平负、全场进球大小、主队进球大小、客队进球大小。投注试验只采用Polymarket 国际站（polymarket.com）上有可核实价量的合约，赛前模拟买入，持有至合约结算。比赛数据、新闻、天气和行情的数据采购预算为零。本地 Codex 沿用已有配置，负责数据源、字段用法、模型与运行维护。正式模拟只买入，持有至平台兑付。临场和赛后数据供判分、结算和故障调查使用。

## 2. 每场比赛怎样产生预测

**统一比分模型。** B0 使用此前完整赛季的联赛频率，B1 只用球队历史，B2 在 B1 上增加可用的人员、新闻和比赛环境。B0 也要从同一份历史比分分布导出各市场概率。B1 以球队攻防强度、主场效应、近期状态、对手强弱为基础，用带时间衰减和低比分修正的 Dixon–Coles 模型建立可复现的基线。加入人员、赛程和比赛条件后，得到主客队各进球数的联合概率。胜平负按比分比较汇总，全场大小按双方进球之和汇总，单队大小按相应球队进球数汇总。比分尾部也计入概率。在训练折内校准期望进球、离散度或低比分参数后重新导出全部概率。验收检查归一、主客方向、各条进球线单调性及高比分尾部的误差。增强特征失效时依次回退到经验证的 B1、B0，展示降级原因和版本。升班马可以使用有许可、已在该截止时点发布的英冠成绩估计先验。[OpenFootball 英格兰](https://github.com/openfootball/england) · [Dixon–Coles 原始论文](https://doi.org/10.1111/1467-9876.00065)

| 输入 | 进入模型的方式 |
|---|---|
| 球队攻防与近期状态 | 调整对手强弱、主客场和历史比赛人数差。结合比分、射门、机会质量，按样本量将升班马和新援估计向合理的联赛或位置平均值收缩。 |
| 球员与阵容 | 记录资格、转会生效日、首发概率、替补人选、预计分钟和位置。前锋看创造与获得机会，门将看面对射门的质量，中后场考虑搭档。按近期常用阵容估计替换的边际影响，避免长期伤情被重复扣分。 |
| 伤停、红黄牌与新闻 | 区分缺阵、出战成疑、伤愈限时、预计首发和正式首发。按赛季及赛事规则核对累计黄牌、红牌、申诉、停赛生效区间和已服场次。模型对未定人选组合加权，消息更新时只重算受影响的组合。历史红牌用于区分十人与十一人阶段，本场牌数只能在赛前估计风险。 |
| 赛程、天气与比赛环境 | 按球员实际出场分钟估算负荷，结合休息日、欧战、旅行、换帅、场地变化和开球时的天气预报。换帅公告、旅行中断或场地变更须能追溯到具体事实。把新闻里确认的影响映射到预计分钟、可用阵容或比赛环境，验证每类因素的样本外增益。 |

**赛前时间线。** T 为当时已知的开球时间。T−24h 封存初判，T−60 分钟封存主评分预测和模拟买入意图。记录主客两队分别何时发布、系统何时收到正式名单，以及热身阶段临时换人。T−60 任一队缺少已收到的正式首发，模型仍输出并评分，主账户跳过该场入场。迟到的名单可生成另一个带时点的旁路预测。若实测长期赶不上，另开预登记的时点实验。改期保存原赛程、原快照和首次知悉变更的时间，新预测另行绑定。2026/27 英超手册 L.23 要求至少提前 75 分钟提交名单，K.95 规定俱乐部最早在开球前 75 分钟公布，免费源的实际到达时间由 M0 测量。[英超手册索引](https://www.premierleague.com/en/news/62625) · [手册条文](https://www.sec.gov/Archives/edgar/data/1549107/000110465926110384/manu-20260630xex4d14.htm)

**每份合约如何定价。** 绑定站点、赛程及改期版本、主客、期间、原始题面与规则版本、进球线、`condition_id` 和买入侧的 `token_id`。保留平台该代协议的原始代币字段（如 `clobTokenIds` 或 `positionIds`）与内部标识的对应关系。一个胜平负玩法可能对应三个分别结算的二元合约。总盘还要定位球队与 Over／Under。以实际挂牌的两侧为准，给每一侧单独取卖盘。常规时间及补时的计算范围以该合约文本为准。用 2∶0、0∶2、平局及边界进球数的兑付表检查映射。整数线、四分之一线如有挂牌，先验算相等、退回、分拆等实际条款，未核实的线只报足球概率。

足球概率以比赛正常完成为条件。对每个买入标识，用 `FV = Σ P(情景) × 该标识在该情景每份的兑付` 得到公平价。情景互斥且穷尽，可包括完赛比分、已确定结果后腰斩、截至指定时间无官方赛果及仍待补赛。待补赛按原合同继续持有，金额和时点按最终兑现计。2026-11-27 诺丁汉森林对切尔西的条款在指定无结果情形下，平局 Yes 兑付 1，球队获胜的 Yes 兑付 0。2026-11-01 利物浦对阿森纳的全场大 2.5 则允许延期后继续等待，彻底取消且无补赛时两侧各兑付 0.5。评估胜平负与计算账本时分别读取体育结果和平台最终兑付。[森林对切尔西规则](https://polymarket.com/sports/epl/epl-not-che-2026-11-27) · [利物浦对阿森纳规则](https://polymarket.com/sports/epl/epl-liv-ars-2026-11-01)

**模拟买入并持有。** 在决策时点冻结证据、报价、最高价、金额和账户可用资金。等待市场延迟后仅用第二份快照模拟执行。两次都需位于实际开球前。按目标份数比较两边累计卖盘的边际价，逐档采用较差价，成交数量以两次实际可支持的较小数量为限。价格越限时减量或跳过。两个离散快照只给出保守的成交假设。记录实际模拟成交量、加权均价（VWAP）、当期费用规则、到账净份数、剩余资金和规则版本。同一深度在同策略内只能消耗一次。价格已含逐档价差与冲击，不重复扣除。每净份入场全成本等于总现金支出除以净到账份数，按实际费用收取资产换算。若正常命中每净份兑付 1，显示的可成交十进制赔率为 `1 / 每净份全成本`。例如含费净成本为每份 0.412，持有到 1 兑付的回报倍数约为 2.43，另列 0 或特殊兑付情景的损益。结算净损益按 `净到账份数 × 最终每份兑付 − 总现金支出` 计算，独立列出已发生的其他现金流。阈值和同场风险见[模拟协议](#protocol)。[订单簿](https://docs.polymarket.com/market-data/prices-order-books) · [费用](https://docs.polymarket.com/trading/fees) · [费用变更](https://docs.polymarket.com/changelog/predictions)

## 3. 让数据源和“怎样使用它”一起迭代

每个来源要有一份可供程序和 Codex 读取的使用说明，写明覆盖赛季、赛事、接口或文件、字段含义与单位、主客顺序、阵容确认标记、预期更新频率、事件与发布时间、系统首次收到时间，以及已验证的用途和备用源。说明随适配器版本保存免费条件、允许的用途、文档地址、样本和已知缺陷。免费条件改变时，停用受影响的入口并切换到已验证的免费备源。

| 环节 | 系统行为 | 证据与产物 |
|---|---|---|
| 发现新增来源 | 按覆盖缺口检查免费公开目录、提供方公告、版本更新及现有来源引用。例如发现单队进球的射门数据有空缺，就定向寻找补充。 | 候选来源、解决的缺口、免费条件、实际英超样本、是否与已有源共享上游 |
| 监测更新 | 在本应变化的时间窗检查最新有效比赛、发布与到达延迟、字段结构、单位、枚举、主客顺序、异常空值。临开球名单的要求高于已经完赛的比分。 | 健康状态、最后成功时间、落后场次、变化样本。接口返回成功但内容冻结也会告警。 |
| 试接和验证用法 | 候选在相同比赛、相同决策时点旁路运行。对比覆盖、及时性、准确性、重复率，并单独比较加入该字段前后的预测表现。 | 分字段结论。例如某源可作赛后球员分钟主源，其赛前阵容只有正式确认后才能作首发证据。 |

## 4. 错误输入怎样纠正并防止复发

1. **发现与隔离。** 数据入库、预测发布前、赛后对账各检查一次，也支持在比赛页直接标错。识别错队、同名球员、错误比赛归属、重复新闻、陈旧盘口、预计名单误作确认、时区错位等。关键字段异常必须在下一笔模拟买入前隔离，依赖它的新预测重算或降级。若影响投注方向且来不及核实，该场暂停新增模拟单。逐次记录发现、隔离、修复和恢复时间，纳入轮报。
2. **追出影响范围。** 每条预测均能沿着“证据版本、字段、球员／比赛、特征快照、模型版本、预测和模拟单”反向查询。确认是单条错误、整个接口的解析偏差、上游更新，还是一条原本正确但后来失效的消息。模型一次猜错不构成错数证据。
3. **修到产生错误的位置。** 给数据补上更正版本和证据，修复映射、解析、字段用法、去重或来源选择。确定性错误可以自动修复。有矛盾的消息保留不同情景与可信度，直到独立证据足以定案。
4. **验证关闭。** 用真实触发案例新增回归测试，重放受影响日期，核实同类坏样本被拦、正常样本能通过，并观察后续批次是否复发。外部提供者持续出错时，切换依赖并监测其恢复。问题单记录原因、修复版本、受影响预测数和复查结果。

纠错范围还要追到训练集、校准器和已经上线的模型。若含点球的 xG 曾被当作非点球 xG 参与训练，修正当前比赛输入仍会留下错误权重。系统应标记受影响版本，重训或回退到经验证版本，再重算仍可行动的比赛。

**首版必须演示一个真实形态的故障。** 接口返回的十一人名单完整，但字段 `confirmed=false`。旧适配器把它当正式首发。系统应定位所有被污染的伤停权重、单队进球概率和模拟单，修正适配器、重算仍未开球的预测，并通过“完整预计名单”和“正式名单”两条相反样本。原来在赛前真实发布的版本继续作为当时表现的审计依据。用纠正输入重放的结果在另一列展示。若更正的是官方赛果，则发布更正后的成绩单和版本差异。

## 5. 先回测，再开启正式前向模拟

M0 从开工起留存数据，M1 可在真实开球前封存技术验证用的影子预测，检验按时交付能力。M2 完成概率回测、M3 完成历史盘口分档报告及账本验收后，在新登记的未来时点启动正式账户。建设期的观测单独标记。每个新增模型或策略也须先完成适用的历史回测，无法还原的输入由之后独立的影子记录评估。

**按决策时钟切片。** 保存当时已知的赛程、实际开球、完赛、提供方发布时间、首次收到时间及修订。时间统一转 UTC，并保留原时区。线上只取截至决策时刻已经发布且已收到的版本。历史复原先验证当时已完赛和数据已公开，若无系统当年收件记录，仅有可核时的同期档案时明示“档案重放”。仅能推定可用时刻的比分可做延时敏感性或日期级研究，不能声称重放了真实 T−24h 或 T−60。训练、选择特征、调参和校准均在各自滚动训练折内完成。用多个验证季选型，2025/26 已在外部审核中揭晓，只作历史确认与回归。真正未知的结果来自今后封存的新比赛。

回归用例采用英格兰当地时间 2021-08-14 12:30 的曼联对利兹。其 T−24h 是 8 月 13 日 12:30，当晚 20:00 布伦特福德对阿森纳还没开球。按比赛日期截取此前结果会读到这场的 2∶0。按审核所用五季快照核对，1,900 场中至少 784 场有这种“计为前一日、却在 T−24h 之后才开球”的赛事。逐季依次为 167、149、152、142、174 场。复核时按伦敦时区，逐场判断有无上一日的另一场比赛开球严格晚于本场 T−24h，同一被预测比赛只计一次。验收时分别污染未来比分、晚发名单和新闻修订，较早预测必须保持一致。重算还要覆盖夏令时、补赛及同日先后开球。

## 6. 每轮联赛的成绩单

按英超官方比赛轮次归属聚合。每场赛果落地先更新进度，延期和待裁定比赛列为待补。该轮比赛均有最终体育状态后发布赛果定稿。Polymarket 尚未兑付的合约单列，全部结算后更新模拟账本。补赛、赛果更正、任务重启和重复通知均生成可追踪的更新，按比赛与版本去重。

**每轮按同一份 0–100 分协议评分。** 默认四项是胜平负（三种结果合为一项）、全场大 2.5、主队大 1.5、客队大 1.5，在实验开始前固定。系统仍为其余挂牌进球线输出概率和分项评分。固定四项避免某一轮因多挂牌十条相似盘口而左右总分。

- 胜平负损失为 `0.5 × 三个结果的 (预测概率 − 实际指示值)² 之和`。实际发生的结果记 1，其余记 0。
- 每个大小球损失为 `(大球概率 − 是否实际开大)²`。同一半球线计一次，小球概率是该线大球概率的补数。
- 单场分为 `100 × (1 − 四项损失的平均值)`，轮次分取各完整比赛单场分的等权平均。每项也分别汇报。所有有正式赛果的合格比赛都在覆盖分母中，漏发单列。存在漏发时标注覆盖不全，总分不得单独用于版本晋级。市场对照与候选对照使用相同比赛和时点。

算例仅用于验算。模型报主胜、平、客胜分别为 50%、30%、20%，最终主胜，这一项的损失为 0.19，对应 81 分。若这场比分为 2 比 0，另外三项大球概率依次为 40%、60%、25%，则损失依次为 0.16、0.16、0.0625，四项合计得分 85.69。这一分值衡量概率误差，实际命中率另列。[Brier 评分定义与取值范围](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.brier_score_loss.html)

同样是“只算了 9 场”，有三种不同原因。若第 10 场尚未补赛，显示阶段报告。若 10 场均完赛、漏发 1 场且其余均分 80，显示覆盖 9/10、已评分均分 80、按漏发场可能取 0 至 100 分计算的全轮范围 72 至 82。若第 10 场只缺盘口而有赛前预测，照常给它打分，只在投注统计中列为不可定价。补赛使用新赛程下真实封存的决策版本，回填原轮一次。

**如何读这份成绩单。** 在审核固定的数据版本上重新跑完 36 组调参，除用时外，结果文件全部数值重现。2021/22–2025/26 的 1,900 场、190 轮中，B0 得 73.55917 分，B1 得 75.46761 分。同场配对提高 1.90843 分，按轮重抽样的 95% 区间为 [1.52918, 2.29039]。B1 的单轮分数标准差为 2.75345 分，另两个相近参数变体的配对区间均跨过零。这次实验能验证评分实现并估算按日截断的基线波动，未检验赛前人员增益和 Polymarket 盈利。2026/27 的局部样本未并入。[实验代码](./review-evidence/score_noise_check.py) · [完整结果](./review-evidence/score_noise_results.json)

**临近开球的两个诊断。** 收盘距离按同标识、同线、相同可比样本，计算按同一合约兑付情景得到的赛前公平价 FV 与实际开球前最后有效双边中点的均方差。正常完赛条件下的比分概率另与体育赛果评分。另按买入标识计算 `CLV = 本标识赛前收盘中点 − 每净份入场全成本`，单位为模拟美元／份。赛中、结算价、其他标识和距开球太久的报价均剔除。按玩法报告匹配率、过期与跳过数、已成交笔数和按比赛分组的区间。分开解释接近收盘、概率更准及扣费后回报。0 笔合格成交时 CLV 与收益率均留空。

## 7. 本地 Codex 如何持续维护系统

| 改动类型 | Codex 可以做什么 | 决定是否采用的证据 |
|---|---|---|
| 源与适配器 | 发现新免费源、检查源迁移、修接口、补采、更新字段字典与使用示例 | 真实样本可用，时间与语义核对通过，正确率、及时率或覆盖达到预设要求，可回滚 |
| 数据用法 | 调整哪些字段可作正式证据、回放特定故障、合并同源转载、修复球员映射与备用源优先级 | 复现原错误，异常和正常两类测试通过，受影响范围重算，质量报告可复核 |
| 模型与投注决策 | 调整阵容情景、预计分钟、进球分布与校准，提出手续费后入场或同场风险规则的候选版本 | 冻结指标及阈值，按时间回测，在相同未来比赛并行预测。模型达到第 10 节的优效、分项与覆盖条件后，由具名审查人确认切换。改变入场阈值、资金或风险规则时独立审议并登记新协议 |
| 评测与运维 | 提议改进评分、报告、任务重试和监控，更新维护说明 | 评分规则若改变，建立新协议版本，以同一协议重评旧模型和候选。数据快照、原始成绩和历史账本均可追溯。 |

本地维护任务从与安装版本一致的源码取受支持的模块，按白名单生成已完轮汇总及采集健康数据。未揭晓的试验期间屏蔽结果；私有运行库、任意任务正文与依赖原件只通过不透明引用关联。研究作业通过只读的 `codex exec` 返回结构化笔记、补丁、源字段或模型假设。记录提交、输入与输出摘要、重试与核验结果。确定性补丁在隔离副本核对能否应用，再交给代码审查与回归；支持的模型配方用固定历史在独立目录回放。免费源候选须登记许可、观测到的字段与独立参考源。模型及选单在预登记未来窗口封存，获具名确认后才切换。发现坏数据时隔离原件，以版本化纠正与重放记录影响。Codex 暂不可用时保留失败日志，采集、预测与评分照常运行。[本地研究操作](./MATCHDAY.md)

## 8. 多子代理并行开发与运行

设一个本地调度器，按任务依赖派工。多个子代理可以同时开发不同模块、分析同一份只读快照或验证不同假设。定时采集、概率计算、评分和记账由可复现的普通程序执行，Codex 用于发现资料、研判异常、修改代码和设计实验。并发数、超时和各免费来源的请求频率按机器和服务可承受的负载配置，临开球任务优先于批量研究。[Codex 子代理](https://developers.openai.com/codex/subagents/) · [Git 独立工作树](https://git-scm.com/docs/git-worktree)

| 工作组 | 可以并行做的工作 | 必须等待的输入或验收 |
|---|---|---|
| 数据源与球队新闻 | 各组分别维护数据适配器，检查上游更新、球员身份、伤停、停赛、阵容与场外消息 | 确认比赛实体、字段含义和证据可用时间后，发布版本化输入 |
| 盘口与模拟投注 | 各场并行核对全场及单队合约，采集不同进球线和订单簿 | 入场需要同场同刻的封存预测、有效报价和账户风险检查 |
| 模型与评测 | 在独立工作树和相同输入快照上，同时运行基线、正式模型和候选实验。回测折可并行，各折独立拟合。 | 比较前锁定候选和指标。赛果落地才评分，合约结算落地才入账 |
| 质量与集成 | 独立检查数据泄漏、证据、代码差异、回放和回滚，汇总各组结果 | 共享接口变更有一名集成者负责。通过对应验收后统一发布正式版本 |

每个任务有稳定编号，记录对象、截止时点、快照哈希、配置及代码版本，输出证据、测试和状态。不同任务使用独立工作树或输出目录。调度器为运行中的任务分配有期限的执行权。进程崩溃时可重新派发，过期进程恢复后也不能覆盖已经发布的结果。缓存相同源请求和公共特征，记录排队时间、处理时长、重试次数和模型用量，便于找出实际瓶颈。

各代理可以并行提出模拟订单，由同一账本按预先约定的顺序核对资金、同场风险和同一快照下的剩余挂单数量，在一个事务里完成成交与扣费。每个订单意图和每笔结算都有唯一编号。重试不得重复消耗同一档流动性，期末余额和份数都能按实际成交、费用与兑付逐笔对账。不同候选策略使用独立模拟账户，才可以公平地比较它们各自单独执行时的表现。

**首版并行验收。** 准备相同的代码、快照和随机种子，分别串行、并行跑同一轮，比较评分、订单、最终净值和实际耗时。途中终止一个任务并重新派发，同时注入一次主客标识互换和一条重复结算通知。用 2 比 0、0 比 2 等比分验证盘口映射。错误方向须在成交前被隔离，正常订单的成交、费用、兑付各记一次，恢复后账本和串行基准一致。

## 9. 开发顺序与整体验收

适合部署在单机。Python 程序执行采集、预测、评分、回测和记账。按来源和日期追加快照，热档以内容摘要保存原件，冷备份可启用 gzip，SQLite 管理比赛、版本、幂等作业和模拟账户。账本单写者顺序提交，模型、来源核验、不同回测折和独立模块可多子代理并行。六个用户入口为比赛详情、数据源、轮次成绩、错误与修复、实验与版本、并行任务。早期可先生成静态页面，再逐步接通全部追查入口。

| 里程碑 | 首版内的完成证据 |
|---|---|
| M0 立即归档 | 拿到首份原始样本即可并行启动 M1。回补过往行情，测主客首发实到时间、盘口覆盖和断线缺口。演练异机恢复。 |
| M1 球队模型与轮报 | B0、B1、两次赛前封存、四种玩法与逐轮评分能跑通。先积累建设期影子记录，演示漏发、延期和缺盘口。 |
| M2 历史概率回测 | 固定数据和环境，逐季滚动训练与比较，交付可复现的逐场预测、配对区间、校准及实际覆盖。 |
| M3 历史盘口与模拟账户 | 验收映射、A/B/C 分档报告、含费成交和特殊兑付。有 A 样本才报告相应模拟收益。M2、M3 均验收后，新窗口启用正式前向模拟。 |
| M4 人员、场外信息与纠错 | 人员、新闻和天气要有采集／录入、特征、情景预测与消融评估的完整通路。演示新源试接、字段用法修复和纠错追到训练集／校准／正式模型。证据不足的特征保留影子标记。 |
| M5 多子代理及整体验收 | 六个入口全部可用。验收新增源、候选登记、模拟晋级与回滚，以及并行和串行的一致性、进程恢复和重复结算。记录真实耗时和用量。 |

工程验收看能否复现、按时评分、核对买入与结算、纠正并防复发。研究成绩另列多季与前向概率质量、同刻市场差距、按分组的 CLV 与净收益。工程上线不以短期盈利为条件，统计晋级和收益声明各自需要证据。首版发布随附实际历史回测、覆盖和缺口报告、协议、逐轮成绩、模拟账本、坏样本及可还原的版本清单。工作包 P01–P12 的依赖、分工与交接材料见[开发计划](./polymarket861-EPL-development-plan.md)。

## 10. 实验协议与初始参数

以下数值是国际站纸面试验的初始设计值。保留费用、风险和来源选择的生效版本。里程碑只引用本表。首个窗口前将参数、单位、排除条件、主统计量和揭晓时点登记成机器可读配置。每次修改在新窗口生效，留存旧版及差异。

| 项目 | 首版初值与验收口径 |
|---|---|
| 时间、采集与及时性 | 预判 T−24h，主评分与买入意图 T−60 分钟。从 T−7 天到 T−48 小时的常规盘口按小时采样，之后至赛前 3 小时每 15 分钟，最后 3 小时每分钟，并在两个决策点和临开球定向采样。分别保存请求、服务端事件和本地收到 UTC 时间。两次应采未收到有效响应即记录故障，另留内容指纹识别“有响应、内容冻结”。名单按主队、客队和双齐分别报成功数／应有数及到达时间分位数。 |
| 报价与执行 | 第一份取截止前最近且新鲜的完整双边簿，意图在决策时点冻结。执行采样目标为意图时点加 `max(5 秒, 当时 secondsDelay)`。在该目标时刻定向取同一标识的完整双边簿，5 秒内未收到合格响应就跳过本次入场，不等待下一次有利报价。报价观测距决策或执行时点均须 ≤30 秒，且各次价差 ≤0.04 模拟美元／份。区分安静市场的旧变动时间与新鲜完整回执，断流或缓存时间无法核实则跳过。使用当时实际最小单量、价格最小变动、市场开放状态和费用精度。第二次行情仅允许缩量或放弃原意图。临开球收盘参照也需双边、同合约、开球前 30 秒内实际收到且未进入赛中，否则 CLV 缺失。 |
| 公平价与信号 | 正常完赛先算比分分布，再映射成逐合约兑付。无结果概率尚无校准样本，先将特殊结果总概率在 0–1% 作敏感性区间，覆盖可适用的情景与对所买标识最不利的兑付，再报盈亏平衡所需概率。相同净份口径下，保守公平价减去含费成本 ≥0.02 模拟美元／份才允许入场。公平价相对可比同刻中点的绝对偏离 >0.08 时，主账户本次跳过并记录异常，另行核验。规则、价量、费用、时间或主客双名单缺失，记录原因并跳过模拟单。 |
| 仓位与账户 | 默认每意图最多支出 50 模拟美元（含费），同场所有持仓在任一相容比分或规则允许的非正常结算情景下最坏净损失 ≤150。另受账户可用现金约束。按赛前固定顺序及同一策略剩余深度成交。每个策略版本独立账户与账本，默认初始现金 10,000 模拟美元。估值方法在窗口前固定，亏损、费用、资金占用和账面回撤可逐笔复算。 |
| 费用与兑付 | 按 `feesEnabled`、`feeSchedule` 或对应协议的实际等价字段、费率生效时间、收费资产及逐档精度记账。历史费表缺失不进 A，现行费率重算只作压力情景。按最终兑付向量对账，若以 0.40 买入 10 份、每份最终付 0.50，收回 5、扣费前盈利 1。 |
| 评分与校准 | T−60 每场固定胜平负、全场大 2.5、主队大 1.5、客队大 1.5，各占四分之一。分项损失、对数损失、等频或预设分箱的样本量和校准图同时保留。按比赛等权，同场同刻比较。100 场以下的前向样本照常出轮报。 |
| 候选和揭晓窗口 | 0.3.0 新登记的模型及选单窗口按起始轮连续覆盖 38 个官方轮次，可跨赛季。既有同季 38 轮和旧 12 轮登记按各自协议重现。每窗最多 3 个候选，写入累计试验次数，跨窗结论用不重叠的新比赛确认。 |
| 模型晋级 | 主统计量为候选减正式模型的同场 0–100 分差。多季滚动以及覆盖 38 轮、至少 95% 预登记比赛的独立前向配对，两段区间下界均须 >0，前向四分项下界各 ≥−0.5 分，预测覆盖不降且风控通过。新试验以官方轮次为聚类单位，使用聚类标准误、Student t 临界值和 Bonferroni 同窗校正，报告同时 95% 区间。未到预定窗口、仅非劣或结论不清，维持影子。 |
| 选单策略晋级 | 在同一冻结入场阈值及风险规则内，若仅更改可入场机会的筛选或排序，用同场、同预算的含费 CLV 改善作策略主指标。以 `Σ[净份数 × (收盘中点 − 每净份全成本)] / 预登记的比赛预算` 计每场贡献。两策略用同一份赛前冻结的机会表和正预算，对有效收盘的共同样本作配对。主动空仓贡献为零，缺收盘记缺测并披露两侧覆盖，已结算的收益仍可独立计算。历史 A 档和独立前向各须覆盖至少 100 场不同比赛，合格收盘占共同预登记机会 ≥95%，每段至少 20 场有一方模拟成交。两段区间下界均须 >0 且通过风险约束，不能借概率得分晋级。改变限额、评分或风险规则需独立审议并登记新协议。 |
| 源切换与数值复现 | 字段自动升主源先覆盖至少两个完整轮次、20 场适用比赛。身份、时间、方向等关键语义抽查全部通过，及时且有效的覆盖率 ≥95%，披露分母与区间，并与现主源作同场比较。稀有事件字段改用预登记的适用样本与故障样例。原始哈希、订单、费用、兑付及账本按定点精度完全一致，固定依赖与随机种子的概率绝对误差 ≤10⁻⁸。 |
