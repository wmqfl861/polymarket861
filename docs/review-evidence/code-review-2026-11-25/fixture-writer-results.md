# 赛前模拟账本的写入时限

2026 年 11 月 25 日在同一台 Linux x86-64 环境复跑原审查脚本。宿主显示 AMD EPYC 9V74，进程可用 9 个逻辑 CPU，Python 3.12.14，SQLite 3.53.1，测试数据库位于 tmpfs。基线为 `333d1f5`。每档均由正式机会入口处理 21 个合约、42 个方向，结果均为冻结 6 个、跳过 36 个。

在零历史和 4,000 条历史两档，单次机会处理的物理 SQLite 连接由 817 次降至 1 次，账本发布由 42 次降至 1 次。另用五个独立的比赛实体、不同球队及代币，同时调用正常机会入口，共用已有 16,000 条记录的同一主账户。五个线程处理 210 个方向共用 0.532 秒，合计建立 5 个连接、发布 5 次账本摘要。每场仍冻结 6 个方向。

测试采用受控球队、封存预测和通过生产解析器归档的合成报价，固定系统时钟以便逐项比较结果。用时统计的是本地事务，网络采集、真实硬盘同步等待和比赛日上游排队需要在线上纸面试验中另行观测。

## 运行与查询

```sh
python docs/review-evidence/code-review-2026-11-25/decision_window_benchmark.py
python docs/review-evidence/code-review-2026-11-25/simultaneous_fixtures.py --fixtures 5 --history 16000
PYTHONPATH=src:tests python -m unittest discover -s tests -p test_fixture_batch.py
pm861 --data-dir /path/to/data ledger-report --account main
```

模拟资金由 SQLite 的单写事务保护。一个 `opportunity.process` 时点内的冻结、扣款、深度消耗和机会记录一并提交，重复调用沿用已封存的意图。账户摘要提供现金、预留资金和可用资金。完整明细、手续费、收益及重新验证的 CLV 由 `ledger-report` 或看板查询时生成。

本地调用方可用 `with ledger.fixture_batch(data_dir)` 包住同一时点的多笔模拟操作，先在该事务外完成上游抓取。事务提交前会复查封存截止时间及本次使用的交易所原件。跨过截止或已验证原件在处理中改变时，整批撤销，机会日志保留实际缺口。已存在的合规旧意图仍可按归档时间规则恢复执行。
