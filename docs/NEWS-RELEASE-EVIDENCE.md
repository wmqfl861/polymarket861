## 发布回归

Python 3.12 的 354 项测试全部通过，包括在 Chromium 中实际打开预测、新闻更新、来源覆盖和轮报。Python 3.11 与 3.13 各运行相同的 354 项，其中各 353 项通过，1 项浏览器专用测试跳过。Ruff、项目规定的严格类型检查、看板 JavaScript 语法检查、离线构建并安装 wheel、历史对照逐字节复算均通过。

比赛日集成用例中只有源响应和时钟为人工控制。RSS 解析、名单登记、AI 提取、触发预测、B1/B3 封存、独立比分准入和轮报都经过实际代码。线上实采和这些可重复控制的用例分别留存。持续来源故障或停滞积压会进入现有本地 Codex 维护队列，任务仅获得聚合健康信息；模型或代码提议仍走具名审核。

## 复审路径

- 采集、名单及原文证据由 `news_sources`、`news_roster`、`news` 管理。可从 `news facts` 取得摘要并使用 `news article` 重查收件与每次提取。检查来源未读完、同一来源对同一时点给出矛盾信息、名单过期以及后续撤回。
- 球员识别与消息分类在 `news_ai` 和 `news_local_ai`。结论需绑定名单身份、原句和出处，传闻或尚不能确定出场状态的消息可以只留档。
- `news_events` 为有变化的未开赛比赛生成不可变的更新记录。`pipeline` 在两个固定决策窗生成主预测及新闻配对。`news_evaluation` 使用经核验的常规时间赛果重新计算同场评分和覆盖。可独立复查官方已确认缺阵遇到重复转述时的权重，以及未经核验的单一比分能否进入评分。
- 操作步骤、数据许可、本机大模型配置、服务升级和前向评估门槛见[使用手册](TEAM-NEWS.md)。独立审核的结论和复核命令记录在[发布审核](INDEPENDENT-REVIEW-0.4.0.md)。
