# polymarket861 英超首版开发计划

本计划把英超首版拆成 12 个可并行实施的工作包。每个工作包都有输入、交付物和验收证据，全部阶段共同交付同一版系统。[英超首版蓝图](./polymarket861-EPL-v1.md)

## 1. 固定试验口径

- 首批只做英超。赛前预测胜平负、全场进球大小、主队进球大小和客队进球大小。模拟账户按选定 Polymarket 站点的可成交价格买入，持有至合约结算。
- 所有第三方数据使用免费来源。本地 Codex 沿用已有配置，用于源维护、输入用法、代码修复和实验。定时采集、预测、评分及记账用可重放的程序执行。
- 默认在开球前 24 小时和前 60 分钟保存快照，以后者作为主评分和模拟入场时点。首发另行记录首次收到时间。改期、延迟到达和来源更正都保留版本。
- 建设期尽早采集新闻和盘口。模型建成后先完成实际历史回测，再开启正式前向模拟。实验和正式策略使用各自的模拟账户。

## 2. 工作包与依赖

前件表示合并验收所需的输入。接口定稿后，各组即可用相同的带版本样例先行开发，并在前件就绪时换入真实数据。

| 工作包 | 前件 | 实施与交付证据 |
|---|---|---|
| P01 · 实体、时间与数据协议 | 起点 | 建立球队、球员、比赛、轮次、合约标识及映射。定义原始快照、发布／接收／更正时间、预测、订单意图、结算和任务产物的字段。交付一个含改期、同名球员、主客互换和更正旧包的共享样例。 |
| P02 · 免费源和历史比赛 | P01 | 导入英超赛果、统计和赛程，建立免费源目录及字段用法。实现更新监测、内容冻结识别、新源旁路比较、主备切换和重放。交付逐赛季字段覆盖表、未发现更新的告警样例及一个新增源的试接记录。 |
| P03 · 人员、新闻与环境 | P01 | 接入阵容、伤病、停赛、xG、负荷、赛程和赛前天气。抽取新闻事实，保留证据位置，合并同源转载。用一例正式名单晚到、一例消息冲突验证两个赛前时点能看到的差异。交付带来源、可用时间和缺失标记的球员特征。 |
| P04 · 赛事盘口与快照 | P01 | 将站点、比赛、球队、方向、全场或单队进球线映射到实际合约。保存逐档挂价和数量、费用、规则版本及合约最终兑付。用主胜和客胜、两队总进球相同但单队进球互换的比分验证映射，列出缺盘和缺深度的场次。 |
| P05 · 本地并行调度 | P01 | 建立持久任务队列、独立工作树、到期重派和发布权限检查。任务交付记录输入快照、代码版本、证据与日志。演示同一任务由两个进程竞争、一个中途退出，恢复后只发布一个有效结果。 |
| P06 · 联合比分与人员模型 | P02、P03 | 实现球队基线及带阵容情景的比分模型。从一份联合分布推导全部盘口，训练和校准按时间窗执行。输出球队基线、含人员／新闻的候选，以及逐场特征版本。验证尾部概率、概率和、主客方向、不同进球线单调性。 |
| P07 · 独立评分与轮报 | P01 | 用封存预测和官方体育赛果计算四项分、轮次总分、逐项误差和覆盖率。同一轮支持阶段报告、定稿、补赛及赛果更正。交付蓝图算例的 85.69 分，以及延期、漏发、只缺盘口三类对照报告。 |
| P08 · 模拟成交与账本 | P01、P04 | 按决策时点可见的卖盘逐档成交，核对资金、同场风险和剩余挂量，记录费用与兑付。用唯一订单意图、结算事件和事务防止重试时重复扣款、消耗挂量或入账。交付逐笔余额与份数对账、缺盘跳过和特殊结算案例。 |
| P09 · 输入纠错和恢复 | P02、P03、P06、P08 | 将原始事实追踪到快照、训练集、校准器、模型、预测及账本。在下一笔受影响的模拟单前隔离异常。修适配器或字段用法，重放受影响区间，重训或回滚污染模型。交付故障复现、修复和回归证据，保留当时发布的预测与纠正后的重放。 |
| P10 · 首次实际历史回测 | P02、P03、P04、P06、P07、P08、P09 | 执行第 4 节的三个历史试验，封存输入版本、候选清单和指标。交付逐场输出、分季报告、盘口覆盖及可复现配置，分开记录已证实的结果和数据缺口。 |
| P11 · Codex 自我迭代 | P02、P05、P06、P07、P09 | 把来源新增、字段变更、错数复盘和模型实验分派给不同工作组。由独立评测程序验收，按预先约定的指标启用、继续观察或回滚。交付一次来源修复、一次候选实验和可追溯的决策记录。 |
| P12 · 界面、前向模拟与集成 | P04、P05、P07、P08、P09、P10、P11 | 贯通比赛、数据源、轮次成绩、错误与修复、实验版本和并行任务六个入口。历史回测报告完成后开启前向模拟。交付端到端运行记录、恢复演练和第 6 节的交接材料。 |

## 3. 多组并行实施

| 阶段 | 同时开展 | 合并点 |
|---|---|---|
| 一 · 对齐接口 | 数据、盘口、模型和账本各提供一条输入输出样例，调度组整理 P01。 | 用同一比赛和两个截止时点对齐标识、时间和合约结算口径。 |
| 二 · 分路开发 | 数据组做 P02，人员组做 P03，盘口组做 P04，调度组做 P05，评测组做 P07。界面可使用 P01 样例联调。 | P02/P03 汇入比分模型，P04 汇入模拟账本。 |
| 三 · 建模与回放 | 模型组做 P06，账本组做 P08。质量组准备 P09 故障案例。接口稳定后，各回测折可独立拟合，基线和候选可并行计算。 | 质量组核对输入来源、派生关系、订单和结果，锁定协议后执行 P10。 |
| 四 · 迭代与交付 | P11 的工作流可与 P10 历史计算并行。独立评测方保管未揭晓结果。界面组接入正式产物。 | P10 完成后，由 P12 运行逐轮前向流程。策略升级依靠事先约定的回测和独立前向证据，样本不足的候选继续观察。 |

调度器让临开球任务优先，按机器负载和来源限流配置并发。各代理共享只读输入，写到各自的工作树或结果目录。共享接口设一名集成者。相互独立的候选可并行，正式结果发布和账本资金变动按同一确定顺序提交。任务页显示负责人、前件、阻塞原因、产物、用时、重试和资源消耗。

## 4. 历史回测和每轮评分

1. **先登记，再揭晓。** 建议以 2021/22–2023/24 开发，2024/25 选择模型与阈值，2025/26 用作第一次独立盲测。按真实开球和信息可用时间滚动重放。候选、版本、参数和比较指标统一封存后一次揭晓。已查看的盲测样本转作回归资料。
2. **分别跑三种试验。** 全部可用赛果用于衡量比分预测。能证实赛前已知的新闻、人员和天气用于比较增益。仅同站点同合约、当时卖盘数量和费用可核实的比赛用于投注收益回放。逐项公布总体场数、可用场数、缺失和偏向。即使盘口样本为零，也报告覆盖情况并继续前向归档。
3. **验证计算口径。** 胜平负用三分类 Brier 损失乘 0.5，其余三项用二元 Brier 损失。默认固定全场大 2.5、主队大 1.5、客队大 1.5，与胜平负四项等权。单场分为 `100 × (1 − 四项平均损失)`，有完整预测和赛果的比赛等权进入轮次均分。其他实际挂牌线给分项结果。基线、市场和候选在相同比赛与时点比较。
4. **分开触发赛果评分和财务结算。** 比赛终场并取得官方结果后更新本轮成绩。延期列待补，补赛使用新开球时间对应的真实封存预测，回填原轮一次。有预测且缺盘口的场次照常评分。漏发必须列入覆盖分母并给全轮分数范围。合约兑付到达后才更新账本，轮报另列费用、净收益、回撤、数据事故及未完成事项。

## 5. 验收演练

| 场景 | 通过时应留下的证据 |
|---|---|
| 接口持续返回成功但内容停更，且备用源的 xG 字段定义有差异 | 告警能定位停更时段，明确两源是否含点球或已经按 90 分钟换算。适配器用正常与异常样例通过回归，免费条件和字段用法同步更新。 |
| 预计首发被认作正式首发，或含点球 xG 混入非点球训练特征 | 找出受影响输入、训练切片、校准器、上线模型、预测和模拟单。隔离字段，回退或重训模型，重算仍可决策的比赛。用证据区分赛前真实记录与修复后的回放，保留使故障不能静默复发的测试。 |
| 历史回放遇到赛后才公布的名单、当天晚场赛果和无深度报价 | 早场特征没有使用未来信息，缺深度只影响交易样本，四类预测的覆盖和时间切分可逐场复核。 |
| 一轮十场，取九场已评分且均分 80，分别构造第十场延期、漏发、仅缺盘口三个案例 | 延期时出阶段报。全部完赛但漏发时报告 9/10、已评 80 分及全轮 72–82 分范围。仅缺盘口时正常给第十场评分。重复补赛通知只更新同一比赛一次。 |
| 相同快照、代码与随机种子分别串行和并行运行，中途杀掉持有任务的进程 | 工作可重派，过期执行者的提交被拒。注入重复订单意图、重复结算和同场争抢有限挂量后，比分分布、评分、成交份数、费用和期末余额与串行结果一致，并记录两次耗时。 |
| Codex 提议新的数据用法或一个模型改动 | 可看到工单、补丁、版本和对照证据，演示采用、继续观察和回滚三种路径。Codex 暂时不可用时，既有程序仍能按时保存预测，待研究任务可恢复。 |

## 6. 首版完成与交接

首版验收以一套可运行系统为单位。接手者应能在干净环境按文档完成以下操作，并能追溯每项输出。

- 按版本安装并启动服务，从免费源同步、补采或读取已归档的同一快照。查阅字段字典、来源许可和已知覆盖缺口。
- 从固定版本重跑 P10，以发布时约定的数值精度复现逐场预测、各类评分、模拟账本和分季报告。给出真实数据的结果，机制演示样例另列。
- 在比赛页查看四类概率、证据和模拟决策，再从轮报追到预测版本与账本。用延期、特殊结算、输入错误走通复查与更正。
- 从并行任务页取回运行记录、故障工单和 Codex 改动，验证同一轮能断点恢复，能将候选版本回退到已验证版本。

交接清单应包含对应代码提交、依赖与运行说明、配置样例、来源清单、数据与模型版本清单、回测报告、轮报和账本样本、故障演练记录，以及下一条待处理工作包及其前件。尚在积累前向样本的指标列出当前覆盖和后续验收办法。
