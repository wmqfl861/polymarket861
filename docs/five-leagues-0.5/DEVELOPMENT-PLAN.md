# 五大联赛版开发计划与验收工单

本文件是已审核的原始工作包。当前开发顺序、资金及证据门槛见[复核后的实施计划](IMPLEMENTATION-PLAN.md)，首批实测见[开发交接](DEVELOPMENT-HANDOFF.md)。

提案基线为 0.4.2。下表中的文件是将来需要审查的现有模块，字段、入口和工作包是下一版的设计。审核通过后的首批开发目标，是让同一场国内联赛从赛程注册贯穿到四项概率、赛后评分、纠错与轮报，再让合格的 Polymarket 合约贯穿到模拟兑付。[总体蓝图](README.md)

## 工作包、依赖与交接

| 工作包／负责方向 | 前置 → 可以开展的工作 | 预计工程人日 | 交给下一组的产物与验收条件 |
|---|---|---:|---|
| W0 · 协议与英超基准 | 审核定稿 → 维护者冻结原数据、输入及已登记窗口，建立五国逐季规则与字段目录。 | 2–3 | 固定本次基线、输入摘要、旧比赛 ID／账本引用、英超 1,900 场四分、旧轮报和近场新闻案例。登记样本期、主指标、候选上限、缺测口径和资金策略。 |
| W1 · 身份、赛季与数据库 | W0 → 存储组改赛事/阶段、赛季成员、来源 ID、排期版本与时间线，提供查询与写入契约。 | 5–8 | 五国空库均可建档，英超原有 ID 和查询可还原。同名球队跨国、二队、女子队、转会前后、夏令时、延期同一场、附加赛独立等回归通过。 |
| W2 · 免费赛程、赛果和纪律 | W0 后并行取样，W1 后接入 → 四国适配与英超回归分别开发，逐字段登记来源授权、血缘、时效、复收标准。 | 7–11 | 25 个联赛赛季逐项对账，包括固定来源缺件、可补证、行政判罚、未决与常规终场。在至少两轮试运行中逐场提供来源及冲突；不足字段有候选和下一次取样安排。 |
| W3 · 球员与五语新闻 | W0 后准备权利与盲标样本，W1 后对接 → 球员身份、赛季名单、有效日期、覆盖 96 队的来源清册、事件驱动与本地 AI。 | 6–10 | 五语（英、西、德、意、法）分别给出实体和状态盲评、确认缺阵误报、双端球队覆盖与延迟。每条用于预测的事实可查证，译稿、传闻、过期消息和撤稿有明确处理。[验收细则](NEWS-AND-OPERATIONS.md) |
| W4 · Polymarket、规则与账本 | W0 后整理模板和抽样报价，W1 后绑定赛事 → 发现目录、代币绑定、规则版控、定向双时点抓取、模拟持仓和兑付。 | 7–11 | 五国各有逐合同证据清单和覆盖漏斗。对三个胜平负合约、全场及双方单队大小验证方向、补时、延期、已确定大球、void/特殊兑付；未见规则只记录事实。重复市场、无盘口和缺费表均可说明去向。[实测对照](POLYMARKET.md) |
| W5 · 基线、增强模型与历史回放 | W1 后先接标准基线，W2/W3 提供可用性与盲标 → 建立 B0/B1 分联赛基线，候选 B2/B3 与跨国共享试验。 | 6–10 | 每个联赛每个赛季输出训练折、启用时间、样本、四分项和区间；同一比分分布导出各半球线。盘口缺失仍可检验预测概率；严格赛前档、时间假设档和市场收益分别报告。[模型方案](MODEL-AND-VALIDATION.md) |
| W6 · 调度、轮报、看板及本地 Codex | W1 的接口稳定后开发，集成 W2–W5 → 单机并行收件、单写事务、恢复，分联赛轮报、来源/模型试验工单。 | 5–8 | 可同时处理五国周末、延期跨轮、网络中断、重复通知及来源改版。一个联赛阻塞不会饿死其他联赛。看板可从某场分数进入当时输入、预测、报价及错误修正。 |
| W7 · 端到端、回测与演练 | W2–W6 → 独立验证组使用固定输入、模拟故障和真实公开样例回放。 | 4–6 | 英超兼容报告、五国历史成绩单、覆盖与授权清单、只读真实试采报告、成本与恢复报告。对每个缺件逐项判定是否阻断字段、模型、模拟账户或整联赛。 |
| W8 · 独立复核与交付 | W7 → 与实现人员分离的审查负责人，复核统计、条款、数据治理、隔离、回滚。 | 3–5 | 向 Claude 提供源码版本、蓝图差分、复现命令、证据包、各国能力矩阵和已知缺口。维护者按实际证据放行相应能力，新窗口开始后持续收集。 |

预估工程量合计 **45–72 人日**。按三至四条工作线并行、共用接口在首周冻结，预计 **4–7 周**交付可安装的研究与纸面运行候选版。该估计覆盖文档、测试和联调，未计外部许可答复。字段升源需要真实轮次，模型增益需要独立前向窗口，策略需要真实合格市场机会，无法用增加开发人员缩短。若中途加入赛季，有些正式结论要到下赛季才可取得。

以 2026/27 季中才开始采四个新增联赛为例，软件就绪后即可看基线预测、每轮分数和新闻的影子配对。如果没有可接纳的既有严格赛前收据，2027/28 和 2028/29 才可能成为两个完整的严格历史赛季。若某个全新的配方还需在这两季结束后登记并走完一整季前向，依现有正式换模协议，最早到 2029/30 赛季末才可能具备该项放行的时间条件。实际能否通过取决于覆盖及成绩。已获准的研究级报告可更早产生。[正式试验原协议](../model-release-governance.md)

**并行和合并顺序。** W1 独占核心库结构与标识兼容。W2 按国家分工，W3 统一事实格式，W4 独占合约与账本，W5 统一数学接口，W6 负责入口和调度。来源适配器各自带小型许可允许的样本或重放说明；共享模块由其负责人集成。先用英超和德甲各一轮验证共用接口能处理 10 场和 9 场，再用西甲、意甲、法甲补全同一清单。所有联赛从首个可用时点开始积累真实覆盖；试运行只进入隔离的数据目录／模拟账户。

新赛季注册指向规则版本、官方阶段和预期席位，不能从交易所 series 名或来源文件名猜赛季。预测键至少区分稳定比赛、排期版本、截止、模型/协议、运行模式。数据库唯一约束及事务覆盖官方同场映射、封存、买入意图、费用、兑付及修订。导入以来源实体 ID 和内容版本幂等；旧英超 ID 作为可解引用的别名或原有主键，新增联赛不发生碰撞。新安装按新布局初始化，兼容性验收在英超 0.4.2 基准副本上进行。

## 实际资源与免费服务的约束

- **定向采集。** 每个提供方共享请求缓存、配额与退避，带真实身份标识，遵守其接口和用途。优先队列依次保障即将到期的决策/执行盘口、赛前输入、紧邻开球的收盘观测、赛后结果、历史补采。收盘记录独立保留。按服务拆分预算；迟到原件能审计，不能倒填已错过的窗。
- **以同时开球数做容量验收。** 每个联赛先重放一轮，再做五国共 48 场排期、若干场同一分钟开球的负载演练。以 `到期比赛 × 每场目标代币数 × 每个窗口快照数` 计算目标代币观测，再按原生批量接口容量换算请求，叠加执行和收盘时点。记录实际公开限速、限流率、排队延迟、按时收到/应收、未采原因和单写事务等待。两次应采失败触发来源健康事件，重试不得创造较早的收件。
- **磁盘与恢复。** 取一个实际周末测每类响应压缩后体积和每天新增量，按 `实测日原件及索引增量 × 留存天数 + 数据库/WAL 峰值 + 备份及恢复空间` 估算，分别给出日常与峰值。只归档获准材料；备份包含规则版本、原件哈希、排程、密封预测与账本。断电重启重放后，同一输入键与概率在现行数值容差内相同，含费现金、持仓与兑付完全一致。
- **资金竞争。** 沿用每策略 10,000 模拟美元、每意图含费最多 50、每场最坏净损失最多 150 的默认组合约束。五国共享该策略的可用现金与待兑付占款。多个候选争同一资金时，按赛前登记的排序和唯一 ID 打破并列，事务化占款；报告改变赛程或加入联赛造成的机会挤出。[原有报价、账户与费用协议](../polymarket861-EPL-v1.md)
- **日常操作。** 运行者选择全部或指定联赛，查看最近成功赛程、双方新闻与名单、训练样本、时点封存及收盘覆盖；缺源直接看到来源替代和风险。活动中的正式试验在揭晓前向看板和 Codex 只开放时效、覆盖与流程健康。按本地 Codex 工单形成“发现 → 候选 → 隔离试采 → 复跑 → 具名批准或退回 → 可回滚”的版本链。服务的免费额度如是限时试用、耗尽后必须充值，不能列为运行依赖。

## 交付验收清单

| 场景 | 在证据包中逐项校验 |
|---|---|
| 新安装、原项目回归 | 安装并从各正式 CLI 入口注册五国；原英超五季 1,900 场及其固定参数下四项概率回放，冻结英超协议继续得到相同结果；对照旧式英超 ID、链接、报表。 |
| 历史与时点 | 分国逐季列出应有、常规终场、行政、缺件、已校核及纳入训练的场数，复核 8,908 个席位的算式。输入中放入赛后首发、晚发更正、占位时间、赛后转会及未来新闻时，截止前的预测不得变化。 |
| 真实运营与轮报 | 至少一份来自每个联赛的真实赛前技术记录及一次从封存到合格赛果的端到端验证；另列五国同时运行的两轮覆盖、丢窗和修复。没有按时收件或季中才安装则保留缺口，真实拿到前不授予相应“固定窗已验证”状态。正常轮、延期轮、纠错重发三种轮报可复算。 |
| 来源更替 | 新字段自动升主源前，至少覆盖两个完整轮次和 20 场适用比赛，及时有效率 ≥95%，关键身份/方向/时间抽验全部通过，并披露分母、区间和同场对照。德法两轮仅 18 场，至少还需第三轮两场；如只按整轮验收则需三轮。稀有红牌、撤销用预登记事件与反例集。验证撤源、回退、改判后重算和旧快照可读。 |
| 预测研究与正式晋级 | 四项等权成绩和其他实际挂牌线结果逐联赛、时点、玩法报告。分别给出 B0/B1、赛程/环境 B2、新闻 B3 的严格或研究级证据、配对与覆盖。窗口、历史及前向门槛见模型方案；没有相应证据时维持影子。 |
| 市场与模拟账本 | 五国、四玩法按“应有赛程→挂牌→规则和 token 核验→合格双时点簿→成交”逐级计数。T−24h 仅封存预判和行情；T−60m 冻结主账户意图。成交后独立追踪同 token 开球前合格收盘（CLV）和最终兑付（净收益），分别报告两支及交集；未兑付持仓可先有 CLV，缺收盘仍可计算已兑付净收益。无单队历史 A 档样本的单元按实际展示；部分档次仅能展示价格或挂牌。 |
| 故障、根治与复核 | 选每国一个已在文档定位的真例，附原证据与最小可重现样本。错误输入发现后隔离受影响能力、核对血缘、修正规则、扩大同形输入扫描、重放并记录上下游影响。独立审查者从全新数据目录按清单重现关键清单和至少一轮结果，逐项签收。 |

发布清单包含五国数据与授权目录、模型卡、历史回测、严格覆盖、定时新闻配对、盘口与结算漏斗、恢复报告和中文操作手册。每项注明软件版本、配置版本、证据截至时间、负责人及下一个真实观察窗口。程序就绪可以先发布给用户采集；宣布某联赛的正式新闻增益或可成交策略有优势，另须完成该项独立评估。[模型与统计验收](MODEL-AND-VALIDATION.md) · [原正式治理协议](../model-release-governance.md)
