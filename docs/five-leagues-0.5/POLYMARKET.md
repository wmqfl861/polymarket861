with open("docs/five-leagues-0.5/evidence/market-season-2025-26.tsv", encoding="utf-8", newline="") as f:

for scope in ("epl", "lal", "bun", "sea", "fl1", "ALL"):

## 从目录识别到定价

| 目标 | 识别方式 | 实施时需拦截的实例 |
|---|---|---|
| 胜平负 | 主赛事 `moneyline`，以真实队名或明确的平局问题分别绑定主胜、平局、客胜；每份读取 Yes 和 No | 任一队的 No 同时含平局及对方胜；不能用它补缺少的第三份合约。2025 年周末的 144 份胜平负原件缺少类型，须用主事件、原问句和标题严格恢复。 |
| 全场大小 | `totals`，核对整场、双方身份、数字阈值、Over 和 Under | 角球、半场、让球和精确比分即使有相同数字也应排除。整数走水与四分之一盘拆注另验明文规则。 |
| 单队大小 | `soccer_team_totals`，核对全场、参赛球队、group 标题、slug 里的 home/away、阈值和两枚代币 | 单队大小经常在 `-more-markets`。不能按球队出现次序猜主客，也不能用全场或对手的大小盘口替代。 |
| 规则和代币 | 重新绑定 `conditionId`、原文 SHA、声明的 API 版本及 outcome 标签；v1 查 `clobTokenIds`，声明 v2 时核验 `positionIds` | 不明版本、同一 ID 指向两个结果、文本与盘口不同、盘口所属赛制不明，均记录具体原因并暂停该合约进入纸面账户。 |

在临时调查进程中仅放开比赛 slug 前缀，分别将 1,152 份映射成功的合同原文、队名、大小线和方向交给 0.4.2 原版 `ledger_terms._interpret`。英超 240 份通过，四个新增联赛 912 份全部因未登记的参赛方、时段或规则抬头被拒。0.5 应增加按联赛、市场种类和生效期审批的模板，保存已核实的来源、期限时区、弃赛时已确定的结果、待重赛、判定比分、无结果、兑付后修订等分支。原文变化时按条件隔离并重放测试，已有订单继续绑定入场时原件。现行英超解释器和历史模板均需保留回归样本。实测页面的结算来源依次指向五国各自联赛，意甲示例还列有时间限制及备用信息源；其合约条款与第三方网站的数据使用许可应分别登记。[0.4.2 规则解释器](../../src/polymarket861/ledger_terms.py) · [意甲实际条款](https://polymarket.com/sports/sea/sea-ven-bol-2026-11-27) · [文本检查计数与 SHA](evidence/polymarket.json)
